# App / PC 端构建指引

## 一句话

代码写完了，平台壳也生成好了。你只需要跑两条命令就能出包。

---

## 一、首次构建（只需做一次）

### 1. 生成平台壳（如果 `windows/` `android/` 目录不存在）

```powershell
cd D:\WorkBuddyFILE\CreatorBox\app_flutter
python tools\gen_platforms.py
```

它会从你本机的 Flutter SDK（`D:\dev\flutter`）渲染官方模板，生成
`windows/`（CMake 工程，15 文件）与 `android/`（Gradle 工程，20 文件）。

> 换机器或换 Flutter 版本时重跑即可。已存在的文件不会被覆盖。

### 2. 装依赖

```powershell
flutter pub get
```

**必须联网**，拉 `http` / `shared_preferences` / `uuid` 三个包。

### 3. 出包

```powershell
# Windows（PC 端）
flutter build windows --debug

# Android（App 端）
flutter build apk --debug
```

> ⚠️ **先用 `--debug` 验证**。debug 编译快、报错信息直白，
> 确认能跑起来了再 `--release`（release 需要签名配置，Android 端尤其）。

## 四、后端必须先启动

App / PC 端是**纯客户端**，所有数据走服务端 API：

```powershell
cd D:\WorkBuddyFILE\CreatorBox
.\start-server.ps1
```

服务地址默认 `http://127.0.0.1:8080`（见 `lib/config.dart`）。
改成局域网其它机器：`AppConfig.apiBase` 填 `http://192.168.x.x:8080`，
注意服务端要绑 `0.0.0.0` 而不是默认的 `127.0.0.1`。

## 五、已知限制（不是 bug，是范围）

1. **App 端不做本地下载**——直链由服务端解析，YouTube 直链绑定解析出口 IP，
   本机下载能力属于 v4 §2.3 规划的「本机引擎」，尚未做。
2. **App 端不做 BGM 试听**——需引入音频播放器原生依赖，收益不抵编译风险；
   存素材库后可在小程序端试听（两端同库）。
3. **服务地址是硬编码的 http**——生产环境应改 https。

## 六、常见问题

**Q：`flutter pub get` 卡住或超时**
A：国内网络访问 pub.dev 不稳。用镜像：
```powershell
set PUB_HOSTED_URL=https://pub.flutter-io.cn
set FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn
flutter pub get
```

**Q：`flutter build windows` 报 CMake 相关错误**
A：确认 Visual Studio 装了「使用 C++ 的桌面开发」工作负载。
`flutter doctor` 可以一次性看出缺什么。

**Q：Android 构建报 SDK 相关错误**
A：需要 Android SDK 与对应 build-tools。`flutter doctor --android-verbose` 看详情。

**Q：编译报 dart 代码错误**
A：先跑沙箱内的静态检查快速定位：
```bash
bash tools/cb_check.sh          # dartdevc 真编译
python tools/cb_brace.py lib    # 括号平衡（剔除注释与字符串）
```

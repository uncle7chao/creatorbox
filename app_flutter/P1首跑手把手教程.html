3生成 Windows 平台壳

Flutter 的 Windows 应用需要一堆原生工程文件（CMakeLists、runner 目录等）， 这些由 flutter create 自动生成。你的业务代码不会被覆盖。

执行：

cd D:\WorkBuddyFILE\CreatorBox\app_flutter
flutter create . --org cn.iyama --project-name creatorbox_app
为什么加 --org cn.iyama：决定应用 ID（包名）。 Windows 上影响不大，但Android 上决定了你的应用包名（如 cn.iyama.creatorbox_app）， 上架后就不能改了，所以现在定好。
你会看到：一堆进度输出，最后是
▸ Creating windows/… 之类的行
▸ All done! 或 ✓
▸ 提示 Running pub get in creatorbox_app…（它会自动帮你拉依赖）
执行完 lib\ 目录应该依然存在且文件没变——如果 flutter create 提示 lib\main.dart 已存在并跳过，那是正确的。
提示：如果你看到 Recreating project . 之类的字样，不用慌， 它只是在补缺失的脚手架文件，你写好的 lib 代码不受影响。

你会看到：

▸ 最后列出 + http 1.6.0、+ shared_preferences …、+ uuid … 等

4.5（仅路线 A）Android 真机两项必改

这两项不改，手机上必然连不上服务。这是 Android 独有的坑，Windows 没有。

① 允许明文 HTTP（否则请求被系统拦掉）

Android 9+ 默认禁止访问 http:// 明文地址。打开 android\app\src\main\AndroidManifest.xml， 在 <application> 标签里加一行：

<application
  android:label="CreatorBox"
  android:name="${applicationName}"
  android:icon="@mipmap/ic_launcher"
  android:usesCleartextTraffic="true">
这是联调临时措施。正式上架前要换成 HTTPS 域名，并把这行删掉—— 留着会被应用商店审核挑出来。

② 查你的电脑局域网 IP

手机上的 127.0.0.1 指向手机自己，不是你的电脑。必须用电脑的局域网 IP：

ipconfig
找到当前 WiFi（或以太网）下的 IPv4 地址，形如 192.168.1.100。 这个 IP 填到下一步的运行命令里。
手机和电脑必须连同一个 WiFi，否则即使 IP 对也连不通。
如果电脑用的是 VPN，可能会拦住局域网流量，临时关掉试试。

5静态检查（强烈建议做）

项目里我放了个检查脚本 tools\cb_check.sh，能在真正编译之前 把类型错误、未定义符号等问题揪出来，比等 flutter run 报错快得多。

这个脚本用 Git Bash 跑（不是 PowerShell）。如果你习惯 PowerShell， 在 PowerShell 里直接跑： 
bash D:\WorkBuddyFILE\CreatorBox\app_flutter\tools\cb_check.sh
它诚实设计：如果依赖没齐（没跑 pub get）， 它会明确报 「⛔ 无法给出可信结论」 并退出码 2，而不是谎报「检查通过」。 所以你看到 ✅ 静态检查通过 时，是真的通过了，可以放心往下走。
期望看到：✅ 静态检查通过：无错误
如果报具体错误：把输出整段发我，我立刻改。

6跑起来！

路线 A：Android（先看设备列表）

flutter devices
你应该能看到你的手机型号（形如 xxx (mobile)）。
看不到手机 → 检查：数据线是不是「充电线」不是「数据线」？手机里「USB 调试」开了吗？

然后运行（把 IP 换成第 4.5 步查到的）：

flutter run -d <设备ID> --dart-define=CB_API_BASE=http://192.168.1.100:8080
为什么必须带 --dart-define：App 默认连 127.0.0.1:8080， 在手机上这个地址指的是手机自己。不传这个参数 = 连不上，必然报「连接失败」。
IP 会变（路由器重分配），连不上时重新 ipconfig 查一次即可。

路线 B：Windows

flutter run -d windows
首次会编译，可能要 3–10 分钟，屏幕上一堆 CMake/编译输出是正常的。 之后每次启动只要几秒。
你会看到：标题写着 CreatorBox 的窗口/应用弹出来， 里面有 6 位数字绑定码和倒计时 —— 这就成功了。
常见失败：
报错关键字原因怎么办
连接失败 / SocketException手机连不上电脑的服务① 确认第 1 步服务窗口开着 ② 手机与电脑同一 WiFi ③ 检查 --dart-define 的 IP 写对 ④ 关掉 VPN/防火墙试试
Cleartext HTTP traffic not permitted明文被系统拦回去改 AndroidManifest.xml（第 4.5 步 ①）
Unable to find suitable Visual Studio第 0.5 步没装好跑 flutter doctor -v 看 VS 那行是不是 ✓
No devices found设备没被识别换数据线 / 开 USB 调试 / adb devices 看是否列出
调试小技巧：App 跑起来后，改代码只需在运行窗口按 r（小写）热重载， 不用重新编译。改了 pubspec.yaml 才需要按 R 或完全重启。

7桥接登录全流程走查

App 已经出码了。现在去小程序确认绑定：

步骤操作预期结果
1App 上看 6 位码 + 倒计时码在跳秒
2微信开发者工具打开小程序 → 会员 → 跨端绑定弹出输入框
3输入 App 上显示的 6 位码 → 确定提示「绑定成功」
4盯着 App 窗口，别操作3 秒内自动跳到首页
5关闭 App 再打开直接进首页（免登录，已记住）
6右上角 ⋮ → 退出登录 / 换账号退回绑定码页面
关键验收点：第 4 步必须「自动」跳转。全程不需要你再点任何按钮。
如果 App 一直停在码页面，说明轮询没成功——看 App 窗口有没有显示红色「轮询失败」， 有的话说明服务端断了，把那行字发我。
小程序连的是同一个服务吗？是的。小程序开发者工具里的后端地址也指向 127.0.0.1:8080，也就是你第 1 步起的那个服务。 所以第 1 步的服务窗口绝对不能关——关了小程序也连不上。

操作要点

  • 桌面端最省事的做法：先在浏览器复制链接 → 回到 App 点「从剪贴板读取并解析」 → 直接进结果页
  • 结果页档位应该从清晰到模糊排序，第一档是 1080P，标题形如 1080P（play-api 通道）、720P · 875kbps
  • 点「复制主档直链」按钮 → 拿到最清晰那条直链
  • 点任一档位卡片 → 复制该档直链
为什么档位是空的？如果你看到档位列表空、但页面顶部有提示卡片， 那是因为命中了服务端缓存（缓存不保存档位列表）。 这不是 bug——勾上首页的「强制重新解析」开关再解析一次就有了。
两个「不正常」其实是正常的，别误判：
  • B站只有 1 档 720P —— B站多档需要 wbi 签名，是已知限制， v4 方案 §3.2 已登记为后续专项。与本次改动无关。
  • 抖音没有字幕卡 —— 字幕提取目前只有 YouTube 支持。抖音/B站的字幕还没做。

CB_API_KEY 设置说明

CreatorBox 运营后台 · 管理接口密钥

1启动服务

在项目根目录执行（推荐，密钥会自动处理）：

cd D:\WorkBuddyFILE\CreatorBox
.\start-server.ps1

首次运行时窗口会打印这样一段：

  管理密钥: 首次已自动生成 → server\.api_key
           xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
           ↑ 填进运营后台顶部「CB_API_KEY」框（只需填这一次）

2复制密钥

密钥存在文件里（可用记事本打开 server\.api_key）。 或者在 PowerShell 里一键取出并复制到剪贴板： 

Get-Content D:\WorkBuddyFILE\CreatorBox\server\.api_key -Raw | Set-Clipboard

执行完直接到后台粘贴即可。

3打开后台填入

双击打开 server\admin\index.html，顶部填两个值：

服务地址：http://127.0.0.1:8080
CB_API_KEY：上一步复制的密钥

之后密钥会存在标签页的 sessionStorage 里，关掉浏览器窗口即失效，下次重新粘一次。

为什么非要配这个？

服务端对管理接口采取 默认拒绝：没配 CB_API_KEY 时， 所有 /api/admin/* 返回 503 并锁定。

这是故意的。若改成「没配就放行」，那么一旦运维忘记配置， 卡密、违禁词、用户名单会全部裸奔——任何人打开网址就能操作你的后台。

解析功能（小程序、App 的正常解析）不受影响，那条链路是单独放行的。

常见问题

503后台报「服务端未配置 CB_API_KEY」→ 服务没设环境变量。 用 start-server.ps1 启动就不会有这问题。

401报 Invalid API key → 密钥粘贴时漏了字符（它是 43 位长串）。 重新执行第 2 步复制，别手打。

换密钥删除 server\.api_key 后重启服务，会生成新的。

安全该文件已加入 .gitignore，不会进版本库。 但后台是纯静态页 + 直连，仅建议本机 127.0.0.1 使用。

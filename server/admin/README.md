# CreatorBox 运营后台 · 使用说明

## 一句话

**推荐用浏览器访问 `http://127.0.0.1:8080/admin`**（服务启动后）。
服务地址栏会自动填好，不用手工配——同源访问没有跨域问题。

也可以直接双击 `admin/index.html`，但那样要在右上角手工填服务地址与密钥。

两种方式都**不需要**装任何前端环境、不需要起 dev server、不需要 `npm install`。
这不是偷懒——这是【自用运营后台】该有的形态（见
`docs/CreatorBox-管理后台方案.md` §0：CreatorBox 现阶段只要自用后台，不要 SaaS）。

> `/admin/legacy` 是旧版只读看板，保留备查。

---

## 一、先决条件：服务必须配置 CB_API_KEY

后台所有接口都需要 `X-Api-Key`，而服务端在**未配置 Key 时会拒绝一切管理接口**
（返回 503 并提示配置方法）。这是有意的安全设计：忘配 Key 的部署如果默认放行，
等于把卡密、违禁词、用户名单全敞开。

### 用 start-server.ps1 启动（推荐，无需手动配置）

`start-server.ps1` 已内置自动处理，**你什么都不用做**：

- **首次启动**：脚本自动生成一个 43 位随机密钥，存到 `server/.api_key`，
  并在窗口里打印出来 → 把那串复制到后台顶部的「CB_API_KEY」框
- **之后每次启动**：自动读取同一个密钥，你不用再管

密钥存放在 `server/.api_key`，已加入 `.gitignore`（不会进版本库）。
想换密钥：删掉该文件重启即可。

### 手动启动服务（不用脚本时）

```powershell
$env:CB_API_KEY = "换成你自己的密钥"
python -m uvicorn app.main:app --host 127.0.0.1 --port 8080
```

生成密钥：

```powershell
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

⚠️ `$env:CB_API_KEY = "..."` **只对当前这个 PowerShell 窗口有效**，
换个窗口就没了。长期使用建议写进脚本或系统环境变量。

### Linux 部署

```bash
export CB_API_KEY="换成你自己的密钥"     # 仅当前 shell
```
生产请写进 systemd unit（见 `deploy/creatorbox.service` 模板）。
**不要**把密钥写在命令行参数里——`ps aux` 能看到。

## 二、打开后台

1. 双击 `admin/index.html`（或拖进浏览器）
2. 顶部填两个值：
   - **服务地址**：本机 `http://127.0.0.1:8080`；远程填你的域名
   - **CB_API_KEY**：上一步设置的那个
3. 点「连接」

> ⚠️ 后台是纯静态页面 + fetch直连，没有后端代理，所以**服务地址必须与浏览器同源可达**。
> 如果你要从别的机器访问内网服务，需要改服务监听地址为 `0.0.0.0` 并放行防火墙。

## 三、五个页签能做什么

| 页签 | 能力 | 对应接口 |
|---|---|---|
| **大盘** | 服务在线状态、已接入平台数、最近探针成败、告警记录 | `/api/health`、`/api/health/history`、`/api/health/alerts` |
| **卡密** | 统计（未用/已用/作废）、批量生成（面值天数 × 数量 × 批次备注）、搜索、作废单张| `/api/admin/codes`、`/codes/disable` |
| **违禁词** | 新增自定义词（选类目 + 填替换建议）、停用/启用、删除（内置词=恢复默认） | `/api/admin/banned/words` 系列 |
| **用户** | 总用户/会员/今日活跃统计、按 openid 或昵称搜索、最近活跃时间 | `/api/admin/users` |
| **Cookie** | 查看小红书/微博 Cookie 配置状态、保存 Cookie（保存后立即热加载） | `/api/admin/cookies` |

**违禁词改动即时生效**，不需要重启服务——这是它相比直接改代码的价值所在。

## 四、安全注意

- 密钥存在 **sessionStorage**：关掉标签页即失效，不会在磁盘上留长期副本
- 但这挡不住本机抓包。**正确用法**是只在管理机本机访问 `127.0.0.1`
- 对外暴露时必须：HTTPS + 反向代理限流 + 换强密钥
- 后台**不要**放在公网目录里。它没有登录态体系，唯一的屏障就是那个 Key

## 五、常见问题

**Q：打开就报 503「服务端未配置 CB_API_KEY」**
A：服务端没设环境变量。见§一，设完重启服务。

**Q：报 401 Invalid API key**
A：密钥填错了，或改了服务端环境变量但没重启服务。

**Q：生成卡密后刷新就没了？**
A：不会。卡密存在 SQLite 的 `redeem_codes` 表，只有「作废」或兑换会改变状态。

**Q：内置词点了「删除」为什么变成恢复默认？**
A：内置词写在代码里，「删除」实际是清掉DB 里的停用记录，让它回到默认启用状态。
想真正下线一个内置词，请用「停用」。

**Q：Cookie 保存报 400**
A：Cookie 串太短（少于 40 字符）或不含 `=`。请从浏览器 F12 → Network → 任意请求 →
Request Headers 里复制完整的 Cookie 整串。

**Q：大盘显示"暂无探针历史"**
A：探针默认 10 分钟一轮（`CB_HEALTH_INTERVAL=600`）。刚启动时还没跑第一轮，
等几分钟或去「服务地址」页手动点探测。

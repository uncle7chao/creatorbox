一、准备（只做一次）

需要什么说明状态
Flutter SDK本机 D:\dev\flutter，版本 3.47.5已装
Android SDK + JDK跑真机或模拟器要已装
Python venv跑解析服务（8 个平台的解析器在 Python 里）已装
一部手机可选。没有的话能在电脑浏览器看（见「浏览器版」）可选
关键认知：这不是纯 App，解析靠电脑上的服务
手机 App 只负责界面和下载，解析逻辑在 Python 服务里（8 个平台的接口对接都在那）。 所以电脑上的服务必须开着，App 才能用。App 首页会显示「服务未连」提示，不会静默失败。

二、三步跑起来

  1. 窗口 1 · 开窗口 A，起解析服务 
    cd D:\WorkBuddyFILE\CreatorBox
.\start-server.ps1
    看到 Application startup complete 就绪。这个窗口保持开着。
  2. 窗口 2 · 开窗口 B，连手机并转发端口 
    cd D:\WorkBuddyFILE\CreatorBox\app
adb devices
    手机要开「开发者选项 → USB 调试」，首次连接要在手机上点「允许」。
    为什么要端口转发？ 手机上的 127.0.0.1 指的是手机自己，不是你的电脑。 adb reverse tcp:8080 tcp:8080 建立转发后，手机的 8080 才等于电脑的 8080。
  3. 窗口 B · 跑 App 
    cd D:\WorkBuddyFILE\CreatorBox\app
flutter run
    首次会编译 1–3 分钟。之后改代码按 r 热重载，q 退出。
或者：一条命令搞定全部
依赖、服务、端口转发、启动 App 都串起来了，会自动挑设备： 
cd D:\WorkBuddyFILE\CreatorBox\app
.\run.ps1
依赖已就绪时会跳过 pub get；服务已在跑时会复用不重启。

不玩手机：浏览器版

浏览器里 127.0.0.1 就是电脑自己，不需要 adb 转发：

cd D:\WorkBuddyFILE\CreatorBox\app
flutter run -d chrome

Web 版有两点限制：下载/分享走浏览器机制，部分平台体验略差；但看界面、跑通解析链路完全够用。

三、数据是怎么流的

① 你在 App 输入框粘贴分享文案/链接
② App 调 POST http://127.0.0.1:8080/api/parse（经 adb reverse 转发到电脑）
③ Python 服务识别平台 → 取「平台源头就干净」的原始流地址
④ 返回标题/封面/时长/互动数据/清晰度档位 + 下载地址
⑤ App 展示结果页，你点「保存」→ 下载文件 → 调起系统分享面板
为什么强调「源头就干净」：平台水印是在分发环节才叠上去的，服务器上存着无水印原片。 我们拿到原始流地址就是零画质损失的干净文件 —— 所以整个方案零 AI 模型， 不需要 inpainting、不下载几百 MB 的模型包。

四、常用命令

cd D:\WorkBuddyFILE\CreatorBox\app

flutter run                        # 跑 App（自动挑设备）
flutter run -d chrome              # 浏览器版
flutter run -d <设备名>            # 指定设备（名字从 flutter devices 拿）

adb reverse tcp:8080 tcp:8080      # 端口转发（每次插拔数据线可能要重跑）
adb reverse --list                 # 看当前有哪些转发

flutter devices                    # 列出可用设备
flutter pub get                    # 只装依赖（已装会很快）
flutter run --dart-define=CB_API=http://192.168.1.5:8080   # 走局域网 IP

run.ps1 的参数

.\run.ps1                          # 自动挑设备
.\run.ps1 -Device chrome           # 指定浏览器
.\run.ps1 -Device <设备名>
.\run.ps1 -SkipServer              # 服务已在跑时跳过启动那步
.\run.ps1 -Api http://192.168.1.5:8080   # 手机同 WiFi，走局域网 IP（不依赖 adb）

六、常见问题排查

No supported devices connected

原因① 平台目录缺失。这个项目最初只有手写的 lib/，没有 Android 工程：

cd D:\WorkBuddyFILE\CreatorBox\app
.\setup-platforms.ps1

原因② 手机没被识别。开 USB 调试、数据线插好、手机上点「允许 USB 调试」，然后 flutter devices 确认。

原因③ 手机弹窗拦了。小米/华为等需要在「开发者选项」里额外打开「USB 安装」或「USB 调试（安全设置）」。

绕过去：flutter create . --platforms=web 然后 flutter run -d chrome，先在电脑上看。

App 报 Connection refused / 服务未连

按顺序查三处：

① 服务在跑吗。浏览器打开 http://127.0.0.1:8080/api/health，能看到 8 个平台就是好的。

② 端口转发做了吗。真机上 adb reverse --list 应该能看到 tcp:8080 tcp:8080。没有就 adb reverse tcp:8080 tcp:8080。

③ 是不是明文 HTTP 被系统拦了。Android 9+ 默认禁止 http://。 这个已经在 android/app/src/debug/AndroidManifest.xml 里开了白名单， 但只对 debug 构建生效 —— 确认你跑的是 flutter run 而不是 release 包。

换局域网 IP（转发失败时的替代方案）：

ipconfig | Select-String IPv4# 找到电脑的 192.168.x.x
flutter run --dart-define=CB_API=http://192.168.1.5:8080

前提是手机和电脑在同一个 WiFi，且防火墙放行 8080 端口。

flutter pub get 卡几十分钟

这不是「慢」，是卡死。根因是本机设了代理变量，而 pub 读 http_proxy。

用现成脚本（会临时清代理 + 先做 15 秒预检，不通就直接中止，不让你空等）：

cd D:\WorkBuddyFILE\CreatorBox\app
.\setup-pub.ps1

注意：不要设国内镜像。pub.flutter-io.cn 的归档接口会 301 跳到 storage.flutter-io.cn，那个域名在你本机 DNS 解析不了、走代理被拦成 502 —— 换镜像反而更糟。实测 pub.dev 直连 1.4s/包就够用。

如果它中途卡住，先杀掉残留进程再重试（残留会锁住缓存）：

Get-Process dart,flutter -EA SilentlyContinue | Stop-Process -Force
PowerShell 报「意外的标记 }」或中文乱码

这是编码问题，不是语法错。PowerShell 5.1 会把无 BOM 的 UTF-8 脚本按 GBK 解码， 中文字节被截断导致引号配对失效。

识别特征：报错行号对不上。报错说第 39 行有问题，但第 39 行是 foreach ($v in $proxyVars) { —— 一行 foreach 不可能括号不配对。行号对不上 = 解码问题。

所有脚本都已加 UTF-8 BOM。以后自己写脚本，加完 BOM 跑一遍预检：

python tests\check_ps_syntax.py
改了依赖后报 version solving failed

大概率是两个包间接依赖了不同版本 的 web。本项目遇到过：

share_plus 9.x        要 web ^0.5.0
cached_network_image 3.x 要 web ^1.0.0   → 冲突

解法：用 flutter pub add 包名 让 pub 自己解，它会给出兼容版本：

flutter pub add share_plus
flutter pub add cached_network_image

本项目最终用的是 share_plus ^13.3.1 + cached_network_image ^4.0.4。

升级后要核对 API 变化：share_plus 13 里 Share 整个类已废弃， 新 API 是 SharePlus.instance.share(ShareParams(...))。

点「保存」没反应 / 分享面板不弹

App 的正确流程是：先用 dio 下载到临时文件 → 用本地路径构造 XFile → 调分享面板。

常见错法（我们一开始就犯的）：XFile('https://cdn.example.com/a.mp4') —— 传的是远程 URL，而 XFile 内部走 File(uri)，http 字符串不是合法文件路径，必然抛异常。

下载大文件需要时间，App 里有进度提示。若失败先看是不是网络问题。

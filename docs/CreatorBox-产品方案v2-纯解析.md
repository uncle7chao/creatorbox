# CreatorBox 产品方案 v2 · 纯解析路线

> 版本 v2.0 ｜ 2026-10-04 ｜ **替代 v1.0（作废）**
> 关键变更：**删除全部 AI 像素处理类功能**，产品回归「解析下载 + 配额 + 变现」

---

## 0. 产品定义（先对齐）

**一句话**：粘贴链接，下载**平台源头就干净**的视频和图片。

### 核心原理

抖音/小红书的平台水印是**分发环节才叠加**的，服务器上存在无水印原片。解析到原始流地址即可拿到**零画质损失**的干净文件。

```
作者上传 → 干净原片 → 平台分发时叠加水印 → 用户看到的画面
                        ↓
                解析拿到的就是这个地址
```

### ⚠️ 明确不做的功能（本期）

| ❌ 不做 | 原因 |
|---|---|
| 图片 AI 去水印（端侧 inpainting） | 需要模型，复杂背景成功率上限 60–70%，产品承诺困难 |
| 视频去字幕 / AI 逐帧修复 | 同上 + 视频闪烁问题无法根治 |
| 元数据净化 | 优先级低，非核心 |
| AI 内容检测举证 | 独立需求，暂不并入 |
| 任何 AI 模型推理 | **本方案零 AI 依赖** |

**去水印 = 解析下载，不需要 AI 模型。** 纯代码 + HTTP 请求。

### 边界：什么水印能处理

| 类型 | 能处理吗 |
|---|---|
| **平台水印**（带账号 ID 的半透明浮层，会飘动循环） | ✅ 解析可绕开 |
| 图片/图集类 CDN 水印 | ✅ 解析可绕开 |
| 创作者自制水印（剪辑时打进去的 logo、满屏飘字） | ❌ 已合成进像素，解析无解 |
| 搬运视频带的其他平台水印 | ❌ 同上 |

**产品文案只能承诺"去除平台水印"。** 不能承诺"去除所有水印"。

## 1. 付费模式规划

### 1.1 三层结构

| 层级 | 定位 | 解锁内容 | 实现要点 |
|---|---|---|---|
| **免费 + 广告** | 引流主入口 | 解析不限次 · 720p · 有广告 | 广告 SDK |
| **会员（订阅）** | 主要收入 | 见 §1.2 | 配额校验 + 清晰度参数 + 会员标识 |
| **点数包（按次）** | 增值 | 云端转码 / 格式转换 | 配额扣减 + 异步队列 |

### 1.2 会员权益设计（关键）

⚠️ **不能只放"更高清"。** 因为免费解析拿到的已经是干净原片，画质差距感知弱。

必须包含**非画质类刚需权益**：

| 权益 | 免费 | 会员 | 为什么重要 |
|---|---|---|---|
| **解析次数** | 每日 N 次 | **不限** | 免费额度是成本闸门 |
| **保存次数** | 每日 N 次 | **不限** | 带宽成本项 |
| 清晰度 | 720p | 1080p / 原画 | 锦上添花 |
| **批量下载** | ❌ 每日 1 条 | ✅ 一次导入 N 条 | 🎯 **自媒体人刚需** |
| **历史记录** | 保留 7 天 | **永久** | 重素材管理 |
| **无广告** | ❌ | ✅ | 体验 |
| 图集下载 | 限量 | ✅ 不限 | 小红书刚需 |

> 🎯 **批量下载是订阅的核心卖点。** 自媒体人一次处理几十条，免费额度完全不够用。这是"值不值得订"的分界线。

### 1.3 免费额度设计原则

| 原则 | 说明 |
|---|---|
| **解析不限次** | 成本极低（几个 HTTP 请求），放开有助于传播 |
| **保存限次** | ⚠️ 这是唯一带宽成本项，必须卡 |
| **批量每日 1 条** | 制造"不够用"的感知，引导订阅 |

### 1.4 点数包（按次消费）

**为什么需要**（对标魔音工坊，官方自述 3 种付费模式）：会员订阅之外必须有按量层，覆盖不愿订阅的用户。

```
云端转码 / 格式转换 / 大文件处理
→ 按次扣点数
→ 会员赠送点数包
```

## 2. 功能代码实现

### 2.1 模块结构

```
CreatorBox

├─ 采集层
│  ├─ Android Share Intent 接收      （m0-probe 已验证技术）
│  ├─ 剪贴板监听
│  ├─ 手动粘贴
│  └─ 解析引擎（三级降级）
│     ├─ 一级：移动端 Feed 接口      免 Cookie 免签名
│     ├─ 二级：slidesinfo 公开接口
│     ├─ 三级：移动端 SSR 花括号栈解析
│     └─ 短路熔断：私密/已删除 2 秒返回
│
├─ 下载层
│  ├─ 视频下载（720p / 1080p 双参数）
│  ├─ 图集下载（多张）
│  ├─ 批量队列
│  └─ CDN 中转（saveVideoToPhotosAlbum 需 downloadFile 白名单）
│
├─ 配额系统
│  ├─ 免费额度（解析次数 / 保存次数 / 批量）
│  ├─ 会员无限
│  ├─ 点数包扣减
│  └─ 限流防刷
│
├─ 变现层
│  ├─ 激励视频（3 个触发点）
│  ├─ 插屏（≤2 次/天）
│  └─ Banner
│
└─ 管理后台
   ├─ 平台健康度看板   ⭐ 生命线
   ├─ 合规中心        ⭐ 3.10 硬要求
   └─ 广告与收益看板
```

### 2.2 解析引擎实现要点

**来源**：全部 MIT 许可，可直接商用

| 来源 | 借鉴内容 |
|---|---|
| `parse-video-py` (703★) | 解析器抽象（BaseParser 基类）、FastAPI 骨架、接口契约 |
| `ucmao/media-parser` (342★) | **抖音移动端 Feed 主路径**（403率0%、200ms免Cookie）、小红书双 UA 回退、终端状态短路熔断 |

**平台支持规划**：

| 平台 | 视频 | 图集 | 优先级 |
|---|---|---|---|
| 抖音 | ✅ | ✅ | P0 |
| 快手 | ✅ | ⚠️ | P0 |
| 小红书 | ✅ | ✅ | P0 |
| B站 | ✅ | ⚠️ | P1 |
| 微博 | ✅ | ✅ | P1 |

**禁止**：自研签名逆向（X-Bogus 已死，a_bogus 每周迭代）

### 2.3 降级链实现

```python
async def parse(url):
    # 一级：移动端 Feed（免签名，最稳）
    r = await try_feed_api(url)
    if r.ok: return r

    # 二级：slidesinfo 公开接口
    r = await try_slidesinfo(url)
    if r.ok: return r

    # 三级：移动端 SSR 花括号深度栈
    r = await try_mobile_ssr(url)
    if r.ok: return r

    # 短路熔断：私密/已删除，不再无谓重试
    if r.is_terminal:
        return Response(200, "链接内容已删除或设为私密")
    return Response(504, "解析失败，请稍后重试")
```

### 2.4 清晰度参数

| 清晰度 | 实现 | 带宽 |
|---|---|---|
| 720p | `ratio=720p` | 低 |
| 1080p | `ratio=1080p` | 中 |
| 原画 | 原始 play 地址 | 高 |

**成本控制**：免费用户默认 720p，会员可切 1080p。**解析时即降级返回**，而非下载后再转码（省 GPU 成本）。

## 3. 技术架构

```
小程序（主入口）        App（可选）           管理后台
解析 / 下载 / 广告      批量 / 收藏 / 分享      健康度 / 合规 / 收益
     └────────────┬────────────┘
          FastAPI 共享层
    ┌────────┬────────┬────────┐
 解析服务  下载中转  配额系统  广告聚合
    └────────┴────────┴────────┘
      PostgreSQL + Redis + COS
```

### 3.1 ⚠️ App 端定位需重新考虑

**v1.0 的 App 端建立在"端侧 AI 净化"上，现在这个前提没了。**

那么 App 端还剩什么价值？

| 可能价值 | 说明 |
|---|---|
| **分享直收** | 安卓 Share Intent 接收，比小程序更自然 |
| **不受微信限制** | 无审核红线、无 2MB 包体限制 |
| **批量处理** | 本地队列，不占服务器 |

**决策点**：App 端做不做？做的话定位是什么？

我的建议：**App 端延后到小程序跑通之后**，先做小程序 + 后端。理由是纯解析逻辑完全可以在小程序端实现，没有必须用 App 的场景。

## 4. 里程碑（14–18 周，零 AI 依赖）

| 阶段 | 周期 | 交付 | Gate |
|---|---|---|---|
| **M0 可行性验证** | 2 周 | ① 安卓分享 Intent 探针 ② 解析服务命令行跑通 ③ 小程序审核尺度实测 | 🔴 解析成功 ≥95% |
| **M1 小程序 MVP** | 3–4 周 | 采集 + 解析 + 下载 + 素材库 + 广告 + 会员 | 五平台可用 |
| **M2 后台** | 与 M1 并行 | 健康度看板 + 合规中心 | 3.10 硬要求过审 |
| **M3 商业化** | 2–3 周 | 激励视频 + 配额 + 会员闭环 + 收益看板 | eCPM ≥50 元 |
| **M4 批量与增值** | 2–3 周 | 批量下载 + 点数包 + 云端转码 | — |

**比 v1.0 简单**：不需要 Flutter、不需要 LiteRT/CoreML 转换、不需要时序一致性算法。

## 5. 风险台账

| 风险 | 等级 | 应对 |
|---|---|---|
| **平台改版即失效** | 🔴 致命 | 健康度看板 + 三级降级 + 每日回归测试 |
| 抖音图片 CDN 域名不可控 | 🔴 高 | 服务器中转 + Nginx sendfile |
| 小程序审核驳回 | 🔴 高 | 类目「工具→效率」+ 避开敏感词 + 免责设计 |
| 解析服务 IP 被封 | 🟡 中 | 多节点 + 熔断 |
| 带宽成本失控 | 🟡 中 | 免费保存限次 + 720p 默认 + CDN |
| 魔音等竞品已有解析 | 🟡 中 | 差异化靠速度、支持平台数、批量、体验 |

### ⚠️ 最需要正视的：平台改版

> *"并非所有去水印工具支持抖音最新版本的加密协议。抖音会不定期更新水印算法，长期不维护的工具很快失效。"*

**这个风险是纯解析路线的根本性弱点，没有技术手段能完全规避。** 只能靠：
1. 健康度看板实时监控
2. 快速跟版能力
3. 多平台分散（单平台失效不致命）

| 项 | v1.0（已作废） | v2.0（本方案） |

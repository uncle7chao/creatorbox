# CreatorBox 双端开发方案：小程序 + App（含广告变现设计）

> 版本 v1.0 ｜ 2026-10-04 ｜ 承接《CreatorBox 手机版开发方案 v1.0》
> 触发需求：内嵌广告 → 答案从「二选一」变为「错位分工」

---

## 0. 直接答案

**都做，但不是「并列两个产品」，而是「App 是能力主体 + 小程序是流量与变现入口」。**

内嵌广告这个需求，恰好把两端从"二选一"推成了"必须都做"——因为：

1. **小程序做不了核心功能**（物理约束，见 §1），只能做采集入口
2. **App 做得了核心功能但获客贵**，广告 eCPM 也远低于微信流量主
3. **小程序流量主门槛极低**（UV≥1000，部分资料称已降至 500），获客成本近乎为零

三者拼在一起才成立。**只做小程序，产品没有护城河；只做 App，流量成本压死。**

## 1. 小程序的五道物理天花板（不是优化能绕过的）

| 约束 | 数值 | 后果 |
|---|---|---|
| **代码包体积** | 主包 / 单个分包 **≤2MB**，全部分包 **≤20MB** | MI-GAN 16.3MB + LaMa 44MB = **60MB 模型塞不进**；ffmpeg.wasm 核心单独就 >20MB |
| **WASM 内存** | 沙箱强制 **WASM 内存上限 16 页 = 1MB**，`memory.grow` 超限**静默失败**（无报错，只返回 undefined） | onnxruntime-web / TensorFlow.js 全部无法初始化 |
| **运行时内存** | 峰值 **200–500MB**（视机型），超出即 **SIGKILL** 强杀 | 高分辨率图像流处理必然崩溃 |
| **无 NPU 访问** | 小程序不暴露 GPU 加速推理能力 | MI-GAN 6ms、LaMa 87ms 的红利完全拿不到 |
| **视频处理** | `wx.createMediaContainer` 只支持基础裁剪拼接；Canvas GPU 加速极差（实测 1080P 抽 30 帧 CPU 占用飙至 95%，1 秒视频处理耗时 2.8 秒，而用户耐心阈值 1.2 秒） | **逐帧去水印在手机上不可能实现** |

> 结论：小程序**只能做网络请求类功能**（解析、下载、展示、转码），不能做像素级本地处理。
> 那些"JS 一键去水印"教程 90% 是在用正则匹配 URL 里的 vid 参数拼一个"看似合法实则随时失效"的地址 —— 那是资源溯源，不是去水印，而且恰好是审核最敏感的雷区。

## 2. 广告变现对比：为什么两端必须都做

### 2.1 微信小程序流量主（核心优势）

| 项目 | 数据 |
|---|---|
| 开通门槛 | **累计独立访客 UV ≥ 1000**（部分渠道称 2026 年已降至 **500**），无严重违规记录 |
| 审核时长 | 功能开通**即时**；财务资料 7 个工作日；广告组件 1 个工作日 |
| 分成比例 | 开发者 **50%**；工具类达标（近 7 日日均现金分成 >1500 元或前 1 日买量消耗 >1000 元）额外 **+5% 广告金** |
| 微短剧/小说 IAA 专项 | 人均访问时长 ≥3 分钟，**70% 现金 + 15% 广告金 = 85% 综合分成** |

**各形式 eCPM 实测区间：**

| 广告形式 | eCPM | 适用场景 |
|---|---|---|
| **激励视频** | **50–120 元** | ⭐ 「看广告换高清下载」—— 变现效率最高 |
| 插屏 | 中等 | 页面切换间隙，频次要控住 |
| Banner | 8–20 元 | 工具类页面辅助，单页一个就够 |

> 实操建议：**用激励视频做「付费替代方案」** —— 免费用户可直接下载标清版，看一条广告换高清无水印版。这样既不破坏体验，eCPM 又最高。

### 2.2 App 广告（对比）

| 维度 | 小程序流量主 | App 广告 SDK |
|---|---|---|
| 开通门槛 | UV≥1000，**几乎零门槛** | 需企业资质 + 应用市场审核 + 一定 DAU |
| 获客成本 | 微信搜索 + 分享裂变，近乎为零 | 买量投放，应用商店 ASO |
| eCPM | 激励视频 50–120 元 | 通常低于微信激励视频 |
| 审核风险 | 🔴 **极高**（见 §4） | 🟡 相对宽松 |
| 能否做像素处理 | ❌ 物理不行 | ✅ 可以 |

## 3. 推荐方案：双端错位分工

```
┌─ App（能力主体，隐私护城河）─────────────────┐
│  端侧 AI 净化：MI-GAN / LaMa（LiteRT/CoreML）│
│  视频逐帧：解码 → ROI → 时序混合 → 编码       │
│  元数据净化：C2PA / EXIF / 零宽字符            │
│  素材不出设备 · 无审核红线                    │
└──────────────────┬───────────────────────────┘
                   │ 账号 + 素材云库同步
┌──────────────────┴───────────────────────────┐
│  小程序（流量与变现入口）                      │
│  链接解析采集（纯网络请求）                    │
│  激励视频广告：看广告换高清下载                │
│  账号体系 / 会员 / 云端任务下发               │
└──────────────────┬───────────────────────────┘
                   │
┌──────────────────┴───────────────────────────┐
│  共用后端 FastAPI + PostgreSQL + Redis         │
│  解析服务 · GPU 精修队列(E2FGVI) · 素材存储    │
└──────────────────────────────────────────────┘
```

### 3.1 小程序功能边界（严格遵守）

| 做什么 | 不做什么 |
|---|---|
| 链接解析（抖音/快手/小红书/B站/微博） | ❌ 任何本地像素处理 |
| 素材预览与保存到相册 | ❌ 任何 AI 模型推理 |
| 云端精修任务下发（异步 + 消息通知） | ❌ 视频逐帧处理 |
| AI 内容检测与举证报告 | ❌ 宣称"去除 AI 水印" |
| 会员 / 激励视频 / 付费解锁 | ❌ 诱导分享（合规红线） |

### 3.2 App 功能边界

- 端侧去水印/去字幕（L1 检测 → L2 OpenCV 兜底 → L3 MI-GAN 精修）
- 视频逐帧 + 时序混合
- 元数据与隐式水印净化
- **离线可用，素材不出设备** ← 这是 App 相对小程序的唯一但决定性优势

## 4. 小程序审核：三条必须绕开的红线

⚠️ 去水印类小程序是**下架与封禁的重灾区**，不是"可能有点难"。

| 红线 | 规范条款 | 应对 |
|---|---|---|
| **不为违法行为提供便利** | 《微信小程序运营规范》**4.3** | 不做"去水印"表述，改为"视频解析""素材采集" |
| **侵犯知识产权** | **5.6** | ⚠️ 注意：解析他人平台内容并保存，**本身就在这个风险区**。必须做免责设计 |
| **滥用分享** | **5.1** | 禁止"分享后解锁功能"，禁止诱导分享朋友圈。**激励视频不受此限**（用户主动触发，不强制分享） |

**具体合规动作（缺一不可）：**

1. **类目选「工具 → 效率」**，不选"社交""视频"
2. **文案全程避开敏感词**：「去水印」→「视频解析」「获取素材」；不出现"破解""免费获取"
3. **结果页底部固定 12px 灰字**：「本工具仅提供技术处理服务，素材版权归属原作者，禁止用于商业用途」
4. **用户协议首次打开强制弹窗**，文本可滚动阅读，「同意」按钮需二次确认；协议须写明「您使用的内容需确保拥有合法使用权」
5. **服务器中转下载** —— 视频真实地址常在第三方 CDN 域名且不可控，后端解析后先转发到自己服务器再返回，规避 `downloadFile` 合法域名配置问题（Nginx `sendfile on`）
6. **只解析用户自己分享的内容** + 页面加免责声明
7. **接受被随时下架的风险** —— 运营上把小程序当获客渠道，不当主阵地

> 行业趋势参考：主流平台已能 AI 识别水印擦除行为，治理方向明确从"如何更好地去除"转向"如何在合规前提下提供价值"。**App 才是这个产品真正安全的长线阵地。**

## 5. 排期建议

| 阶段 | 周期 | 交付 | 关键验证 |
|---|---|---|---|
| **M0 双端可行性验证** | 2 周 | 技术验证（非产品） | ① 真机抓抖音/小红书分享 Intent<br>② MI-GAN 许可证 + TFLite/CoreML 转换 POC<br>③ **小程序审核尺度实测**（提一个测试版看驳回理由）<br>④ 微信流量主门槛实测（当前 500 还是 1000） |
| **M1 小程序 MVP（先行）** | 3~4 周 | 链接解析 + 素材库 + 激励视频 + 会员 | UV 跑到 1000 开流量主；解析成功率 ≥90% |
| **M2 App MVP** | 5~6 周 | 端侧 AI 净化 + 视频逐帧 | MI-GAN 端侧 512×512 <150ms；30fps 无可见闪烁 |
| **M3 变现闭环** | 2~3 周 | 广告调优 + 会员体系 + GPU 精修 | eCPM 实测 ≥50 元；GPU 成本模型跑通 |

**为什么小程序先行？**
- 3~4 周能拿到 UV 数据，验证广告变现假设
- 开发成本约为 App 的 1/3
- **且它会反向验证解析服务的真实成功率**（平台改版预警）
- 拿到的 UV 与广告收益数据，直接决定 App 要不要投、投多少

## 6. 与现有 GEO Optimizer 的关系

⚠️ **两者商业模式完全不同，不要混用决策：**

| | GEO Optimizer | CreatorBox |
|---|---|---|
| 模式 | SaaS 订阅制 | 免费 + 广告（IAA）+ 会员 |
| 定价 | ¥0 / ¥299 / ¥999 | 激励视频 + 会员 + 付费高清 |
| 用户 | 跨境卖家（主动付费意愿高） | 泛创作者（白嫖为主，广告敏感） |
| 内容 | GEO 监测报告 | 素材采集与净化 |

可复用：后端技术栈（FastAPI + PG + Redis + 宝塔 + Py3.10.12）、云服务经验、账号体系设计。
**不可复用**：定价与付费设计、目标用户画像。

## 7. 风险清单（广告视角新增）

| 风险 | 等级 | 应对 |
|---|---|---|
| **小程序因侵权被驳回/下架** | 🔴 高 | §4 七条动作全做；App 为主阵地，小程序仅作渠道 |
| 激励视频影响体验导致留存崩 | 🟡 中 | 只做"看广告换高清"，不做强制；频次上限配置 |
| 流量主门槛实为 1000 而非 500 | 🟢 低 | M0 实测；500 UV 前用"免费额度 + 分享获取次数"过渡（注意 5.1 禁止诱导分享，用其他方式） |
| 广告 SDK 在 App 端拉低留存 | 🟡 中 | 优先激励视频，插屏严格控频 |
| 小程序解析成功但无法下载（域名白名单） | 🟡 中 | 服务器中转（§4.5） |
| **App 也面临应用市场对去水印的审核** | 🟡 中 | 定位"素材处理工具"，不做"下载他人平台内容"的显性宣传 |

## 8. 需要你现在拍板的三件事

1. **是否接受"小程序有被下架风险"？** 如果不接受 → 只做 App，放弃广告变现的小程序入口
2. **变现优先级：广告优先还是会员优先？** 建议广告为主（泛创作者白嫖多），会员为辅（重度用户）
3. **App 先做 Android 还是 iOS？** Android 覆盖广、审核相对宽松；iOS 需 Mac + 开发者账号（688元/年）

# 平台解析实现手段全解（参考项目 25 平台逐一拆解）

> **来源**：`parse-video-py`（wujunwei928，MIT）全部 25 个解析器源码逐文件精读（本地 `cb_research/src/parse-video-py-main/`，2026-10-11）。
> **用途**：新平台接入的「施工图」——每个平台给出入口形态、请求方式、关键 headers、字段路径、已知坑，以及**对我们（CreatorBox）的接入建议与优先级**。
> **注意**：参考项目快照于 2026-10-05 clone，平台接口可能已变；动手前先用样本链接验证。

---

## 一、手段分类学（25 平台只有四种套路）

| 套路 | 占比 | 原理 | 代表 |
|---|---|---|---|
| **A. API 直调** | ~40% | 平台有公开/半公开 JSON 接口，GET/POST 即得 | 好看、皮皮虾、微视、度小视、梨视频、腾讯视频、虎牙、Twitter |
| **B. SSR 正则** | ~35% | 分享页 HTML 里内嵌 JSON state，正则抠出来 | 西瓜、小红书、快手、全民K歌、新片场 |
| **C. 二段式** | ~15% | 先 SSR 拿 ID/参数 → 再调第二个 API 拿直链 | 新片场（NEXT_DATA→mod-api）、央视（页面→GUID→vdn API） |
| **D. 混淆解码** | ~10% | 特殊处理：base64 多步解码 / 动态 key / 时间戳替换 | 美拍、最右、梨视频、皮皮搞笑 |

**通用工程模式**（每个解析器都在用）：
1. `fake_useragent` 按 OS 随机（iOS/Android/Windows 分平台指定）——**不是固定 UA**
2. 短链先 `follow_redirects=False` 拿 `location` 提取 ID，再 `True` 跟跳拿页面
3. Referer 必须伪装成平台自身页面（梨视频/六间房/虎牙/新片场）
4. 错误信息从响应体里挖（`filter_list[0].detail_msg` / `errmsg` / `prompt`）透传给用户

## 二、已接入 8 家对照（参考实现 vs 我们，找增强点）

### 2.1 小红书 ⚠️（我们半通：需 Cookie + xsec_token）

**参考实现**（无 Cookie）：GET 分享页 → `window.__INITIAL_STATE__` → **yaml.safe_load**（不是 json！ INITIAL_STATE 里有 undefined 字面量）→ `note.noteDetailMap[id].note`：
- 视频：`video.media.stream.h264[0].masterUrl`
- 图集：`imageList[].urlDefault` → **域名替换** `ci.xiaohongshu.com/notes_pre_post/{id}?imageView2/format/jpg`（spectrum/ 前缀要保留）
- LivePhoto：`imageList[].stream.h264[0].masterUrl`
- 防御：`currentNoteId == "undefined"` → 分享链接过期，明确报错

**与我们的对照**：我们实测（2026-10-07）——无 Cookie 时 `urlDefault` 返回**空串**、`notes_pre_post` 域名替换 **404**，参考项目的无 Cookie 路线**已失效**；我们的 Cookie + xsec_token 路线是当前唯一可行解，比参考更接近现实。
**结论**：小红书保持我们的实现；参考代码只佐证结构假设。差距不在实现手段，在 Cookie 运营（看板热配已建）。

### 2.2 快手 ✅（我们已比参考更优）

**参考实现**：302 拿 Cookie → location 里 `/fw/long-video/` 替换成 `/fw/photo/` → 带Cookie 跟跳 → `window.INIT_STATE`（遍历 values 找 `result==1 且含 photo` 的节点）→ `mainMvUrls[0].url`；图集 `ext_params.atlas.cdn[0]` + `list[]` 拼 URL。

**我们的实现**：`m.gifshow.com/fw/photo/{workId}` **直接 200 无需 Cookie 链**，INIT_STATE 顶层 key 被混淆但我们已处理（花括号配平 + 遍历找节点）。
**结论**：我们已领先参考一步（跳过了 Cookie 传递链）。可抄的小点：`/fw/long-video/`→`/fw/photo/` 的 URL 归一化，长视频链接兼容。

### 2.3 微博 ✅（能力对齐，缺一块）

**参考实现**（无 Cookie）：
- 视频（`show?fid=` / `/tv/show/`）：POST `h5.video.weibo.com/api/component`，body=`data={"Component_Play_Playinfo":{"oid":"..."}}`，`urls` 字典第一条是最高码率（stream_url 是最低档）
- **普通帖子图集**（`weibo.com/{uid}/{postid}`）：m.weibo.cn `statuses/show` API → `pics[]` 按 `large→original→bmiddle→url` 降级取图；API 失败回退桌面页 `$render_data` 正则
- `https:` 前缀补全（返回是 `//` 开头）

**与我们的对照**：视频 POST 与我们一致（我们都无 Cookie 可用）。**参考多的能力 = 普通帖子图集解析**（我们主要处理视频链路）。
**结论**：微博图集帖子解析（statuses/show + $render_data 双兜底）可作为我们的增强项——微博图文帖是小红书内容的镜像池，对素材库有价值。

### 2.4 其余已接入 5 家（抖音/B站/AcFun/搜狐/好看）
参考实现均与我们对齐（抖音我们多了 L3 1080P 通道和图集；B站参考走 dash 需合并，我们 durl 方案更优）。无增强点。

## 三、未接入 17 家逐平台拆解（含活跃度评估与接入建议）

> 活跃度评估基于 2026-10 常识判断，动手前务必验证平台存活与样本链接。

### Tier 1：推荐接入（平台活跃 + 实现简单 + 用户量大）

#### 3.1 西瓜视频（xigua.py，78 行）🟢 难度最低
- **入口**：`ixigua.com/{id}` 或短链（302 拿 location 提取 ID）
- **手段**：`m.ixigua.com/douyin/share/video/{id}?aweme_type=107...` → SSR `window._ROUTER_DATA` → `loaderData["video_(id)/page"].videoInfoRes.item_list[0]`
- **字段**：`video.play_addr.url_list[0]`（**playwm→play 替换去水印**，与抖音同构）、cover/desc/author 全套
- **坑**：URL 末尾不能带 `/`（返回格式不同）；错误信息在 `filter_list[0].detail_msg`
- **建议**：**首选接入**——与抖音同构，我们抖音解析器改个入口 URL 就能用，半天搞定

#### 3.2 皮皮虾（pipixia.py，73 行）🟢
- **入口**：短链 302 提取 ID
- **手段**：GET `api.pipix.com/bds/cell/cell_comment/?cell_id={id}&aid=1319...`（评论接口当详情接口用！）
- **字段**：`data.cell_comments[0].comment_info.item`
- **坑**：`video_high` 可能带水印 → 遍历 `comments[]` 找**同作者**的无水印版本；图集在 `note.multi_image`
- **建议**：字节系，接口风格同抖音，1 天

#### 3.3 Twitter/X（twitter.py，177 行）🟡
- **入口**：`t.co` 短链先 301 解析 → 正则提取 tweet id（支持 twitter.com/x.com/mobile）
- **手段**：GET `cdn.syndication.twimg.com/tweet-result?id={id}&token={token}`
- **token 算法**（无需登录！）：`(tweetId / 1e15) * π` 转字符串，去掉 `0` 和 `.`
- **字段**：`mediaDetails[]` 视频 → 过滤 `content_type=="video/mp4"` 取**最高 bitrate**（非固定下标）；图片 → `type=="photo"` 的 `media_url_https`
- **坑**：token 算法依赖 syndication 接口不封；国内访问需代理（**我们服务器在香港，反而天然可行**）
- **建议**：跨境素材人群有需求，1 天；香港服务器是优势

#### 3.4 腾讯视频（qqvideo.py，104 行）🟡
- **入口**：PC 页路径正则 `/x/(page|cover)/(?:[^/]+/)?(\w+).html`；移动端 `m.v.qq.com` 取 `?vid=`
- **手段**：GET `vv.video.qq.com/getinfo?vids={vid}&platform=101001&otype=json&defn=shd` → **JSONP**（`QZOutputJson=` 前缀要去掉）→ `vl.vi[0]` → `{ui[0].url}{fn}?vkey={fvkey}`
- **坑**：只拿到 fvkey 有效期内链接；VIP 内容拿不到（em 错误码）
- **建议**：影视剪辑人群有价值，1 天

### Tier 2：可选（有真实用户但量小）

#### 3.5 央视网（cctv.py，72 行）🟢
- 页面正则 `var guid="..."` → `vdn.apps.cntv.cn/api/getHttpVideoInfo.do?pid=` → `hls_url`
- **坑**：`h5e/enc/enc2` 高码率流**帧级加扰会花屏**（源码注释明说），只有 hls_url 可用；产出是 HLS 不是 MP4，需走我们的 m3u8 合并
- **建议**：新闻素材人群，1 天（含合并）

#### 3.6 梨视频（lishipin.py，51 行）🟢
- `videoStatus.jsp?contId={id}&mrd={now}`，**Referer 必须**是详情页
- **特殊**：srcUrl 里的时间戳要替换成 `cont-{id}`（防直链）
- **建议**：半天

#### 3.7 虎牙（huya.py，49 行）🟢
- `liveapi.huya.com/moment/getMomentContent?videoId=` → `definitions[0].url`（**视频回放**非直播流）
- **建议**：配合「直播回放解析」产品方向（v4 方案 A 路线），半天

#### 3.8 全民K歌（quanminkge.py，49 行）🟢
- `kg.qq.com/node/play?s={id}` → SSR `window.__DATA__` → `detail.playurl_video`
- **建议**：翻唱/音频提取人群，半天

#### 3.9 新片场（xinpianchang.py，57 行）🟡
- 两段式：`__NEXT_DATA__` 拿 appKey+media_id → `mod-api.xinpianchang.com/mod/api/v2/media/{id}?appKey=` → `resource.progressive[0].url`
- **建议**：专业影视素材，质量高但用户量小，可选

#### 3.10 皮皮搞笑（pipigaoxiao.py，51 行）🟢
- POST `share.ippzone.com/ppapi/share/fetch_content`，body 是**手拼 JSON 字符串**（`{"pid":数字,...}`，不能用 json.dumps 因为 mid 是 null）
- 视频地址要动态 key：`videos[str(imgs[0].id)].url`
- **建议**：与皮皮虾同源系，半天

## 四、半通三家的「参考 vs 我们」对照结论

| 平台 | 参考做法 | 我们现状 | 结论 |
|---|---|---|---|
| 小红书 | 无 Cookie SSR + 域名替换 | Cookie + xsec_token（参考的无 Cookie 路线已失效） | **保持我们的**，差距在 Cookie 运营不在代码 |
| 快手 | 302+Cookie 链 | m.gifshow 直连（免 Cookie 链） | **我们领先**；可抄 long-video→photo 归一化 |
| 微博 | component POST + 帖子图集双兜底 | 视频 POST 一致 | **补帖子图集解析**（statuses/show + $render_data） |

## 五、接入工程注意事项（从 17 个解析器提炼的通用规则）

1. **UA 策略**：按平台指定 OS（梨视频=Windows、微博=iOS、西瓜=Android）——不是统一 UA
2. **短链两跳**：先 `follow_redirects=False` 拿 location 提 ID（西瓜/皮皮虾/快手），不要盲跟
3. **Referer 三大件**：详情页 URL / 平台首页 / 移动端页，缺了就 403
4. **动态 key 三形态**：最右（imgs[0].id 当 videos 的 key）、皮皮搞笑（str(imgs[0].id)）、微博（urls 字典第一条 key）
5. **直链防伪**：梨视频时间戳替换、西瓜 playwm→play、微博 // 前缀补全
6. **错误透传**：平台返回的 detail_msg/errmsg 直接给用户（「作品已删除」比「解析失败」有用）
7. **JSONP 处理**：腾讯视频 `QZOutputJson=` 前缀剥离
8. **yaml 不是 json**：小红书/部分 SSR state 含 undefined，parse-video-py 用 `yaml.safe_load`——我们也应统一（实测已用）

## 六、接入排期建议（结合 v4 方案）

| 批次 | 平台 | 预估 | 依赖 |
|---|---|---|---|
| 第一批 | 西瓜（半天）→ 皮皮虾（1 天）→ 皮皮搞笑（半天） | 2 天 | 无，字节系同构 |

| 暂缓 | 央视（需 m3u8 合并联调）、新片场、微博图集 | — | 按用户反馈插入 |

> 每接入一个平台的标准动作：`parsers/xxx_pure.py`（照参考实现写，UA/Referer/字段宽容解码按我们规范）→ `main.py` 注册 + 域名表登记（domains.py，封面代理白名单同步加）→ knowledge.py 登记（meta 映射）→ health.py 探针样本（3 条池）→ tests 样本 → 小程序平台图标 + 榜单/工具箱文案。

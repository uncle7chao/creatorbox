# AI 文案创作（内嵌 DeepSeek 网页版）

> 2026-10-24 · PC / Android 端可用，小程序端只做占位引导

---

## 1. 为什么是「内嵌浏览器」而不是「服务端调接口」

用户要的是「让用户自己登录 DeepSeek，然后用它做创作」。查证后确认这是唯一可行路径：

| 方案 | 可行性 | 原因 |
|---|---|---|
| **服务端代调 chat.deepseek.com** | ❌ | ① 每次请求要解 PoW（`x-ds-pow-response`，SHA3 WASM 挑战）② 平台检测 TLS 指纹，非浏览器客户端直接封 ③ **致命**：所有用户共用我们一台服务器出口 IP，风控很快会封掉整台机器 |
| 用户提供 token 我们代调 | ❌ | 普通用户不会去 F12 复制 `localStorage.userToken` |
| **内嵌浏览器 + 用户自己登录** | ✅ | 签名 / PoW 由页面自己的 JS 算，请求从**用户自己的 IP**、用**用户自己的额度** —— 零逆向、零伪造 |

### 代价：半自动

- ✅ 我们负责：选模板、生成 prompt、**把素材填进输入框**、**把结果读回剪贴板**
- ❌ 我们不代点「发送」：程序触发的点击 `event.isTrusted === false`，容易被判自动化

**多一步点击，换掉全部逆向风险，这个交换是值的。**

## 2. 怎么用

```
首页「文案创作（用 DeepSeek 改写）」
   ↓
右侧加载 chat.deepseek.com → 用户自己扫码/验证码登录
   ↓
上方填素材（或从解析结果页「用这段文案创作」自动带入）
   ↓
选模板：小红书 / 抖音口播 / 10 个标题 / 视频简介 / 改写润色
   ↓
点「填入 DeepSeek」→ 素材+指令出现在右侧输入框
   ↓
用户自己点「发送」
   ↓
点「读回回复」→ 结果复制到剪贴板
```

**动线设计**：解析结果页加了「用这段文案创作」，把「标题 / 文案 / 字幕」三段自动带过去 —— 省掉「复制→切窗口→粘贴」。

## 3. 五个模板（模板决定 80% 产出质量）

| 模板 | 关键约束 |
|---|---|
| 小红书 | 3 个标题 + 200~300 字正文 + 6~8 个话题标签；**禁「家人们/宝子们」烂梗**；不许编造素材里没有的信息 |
| 抖音口播 | 30~45 秒，第一句必须钩子，每句 ≤18 字（方便字幕），结尾自然引导 |
| 10 个标题 | 覆盖 5 种风格各 2 个；不许用「震惊/必看」违规词 |
| 视频简介 | 60~100 字，三句结构（讲什么 / 价值点 / 引导互动） |
| 改写润色 | 长度 ±20%，**不改原意、不加原文没有的事实**，保留所有数字与名称 |

每个模板都明确写了「不要编造」，因为文案类最容易出的问题就是模型加料。

## 4. 已验证的部分（真跑过，不是推测）

### ① React 受控组件的填入写法

DeepSeek 是 React。直接 `textarea.value = x` **不会生效** —— React 的 value tracker 认为值没变，不更新 state。

用 headless Chrome 实测两种写法：

```json
{"wrong_fired": 0, "right": "ok", "right_fired": 1, "value_now": "填入的测试文案"}
```

- `wrong_fired: 0` → 直接赋值，`input` 事件没触发
- `right_fired: 1` → 原生 `Object.getOwnPropertyDescriptor(...).set` + `dispatchEvent(new Event('input'))` 成功触发

### ② 选择器兜底

页面里放两个 `textarea`（一个 `display:none`）、三个 `.ds-markdown`（中间一个空白）：
- 填入：正确选中**可见的、最高的**那个
- 读回：跳过空白，取**最后一条有内容**的

### ③ 三段 JS 语法

`node --check` 全部通过。

## 5. ⚠️ 未验证的部分（必须你本机确认）

我抓 `chat.deepseek.com` 时**只拿到登录页**（验证码登录表单），没有登录态，**看不到聊天输入框的真实 DOM**。

所以：

| 项 | 状态 |
|---|---|
| 输入框选择器（`textarea` 可见最大） | ⚠️ 基于通用结构推测，**未在登录后页面上验证** |
| 回复容器选择器（`.ds-markdown` 等 5 个兜底） | ⚠️ 同上 |
| WebView2 渲染 / 焦点 | ⚠️ 沙箱无法编译 Flutter，**未跑过真机** |

**如果填入失败**（状态栏会显示 `没找到输入框`），按这个顺序修：

1. 在 WebView 里按 F12 打开 DevTools（`webview_flutter` 默认允许）
2. `document.querySelectorAll('textarea').length` → 有几个？
3. 把真实选择器补进 `ai_create_page.dart` 的 `_fill()` 里 `sels` / `querySelectorAll` 那段
4. 同理修 `_readBack()` 的 `sels`

**选择器都集中在方法开头几行**，改起来只动一处。

## 7. 小程序端：只做占位（不能做真功能）

| 项 | 内容 |
|---|---|
| 位置 | 工具箱 →「即将上线」区 |
| 卡片 | **AI 创作助手 · PC / App 端可用**（角标是品牌橙，不是灰色「规划中」） |
| 点击 | 弹窗「请在电脑端使用：文案创作需要键盘输入和长文本编辑」 |
| 为什么 | AI 生成属微信「**深度合成-AI 创作**」类目，**只允许企业主体申请**，个人主体提审必驳回（且需 DeepSeek 算法备案 + 盖章合作协议） |

⭐ **合规要点**：小程序内**不提供任何生成能力**，只做「告知 + 引导」，
因此不构成「提供深度合成服务」，不需要该类目。

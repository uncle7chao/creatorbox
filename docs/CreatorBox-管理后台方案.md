# CreatorBox 管理后台方案（运营后台，非 SaaS 多租户）

> 版本 v1.0 ｜ 2026-10-04 ｜ 承接《双端方案与广告变现》

---

## 0. 直接答案

**要做后台，但不是做 SaaS。**

你的问题里混了两个不同的东西，拆开就清楚了：

| | 自用运营后台 | SaaS 多租户 |
|---|---|---|
| 谁在用 | 只有你自己 | 别的公司/团队 |
| 隔离 | 无需 | 每租户独立数据/域名/配置 |
| 计费 | 无 | 按租户订阅计费 |
| 白标 | 无 | 换品牌换主题 |
| 代理分销 | 无 | 三级分销体系 |

**CreatorBox 现阶段只需要前者。** 多租户那套是 GEO Optimizer 的需求（跨境卖家、企业客户、要代理/白标），CreatorBox 的用户是泛创作者（白嫖为主），**没有企业客户要隔离，没有白标需求，分销体系对泛创作者无意义**。

而且"多租户 + 代理分销 + 租户计费"这套东西跟 CreatorBox 的**广告变现模式直接冲突** —— 你的收入主体是流量主广告分成，广告收入与用户规模正相关，一旦引入按租户计费，会把精力耗在 B 端销售上，反而丢掉 C 端规模优势。

**但架构上要预留 `tenant_id` 字段**，将来真要做（或跟 GEO 共用基础设施）时不用重构表。

## 1. 🔴 后台不是可选项 —— 微信规范 3.10 是硬要求

> **《微信小程序平台运营规范》3.10：「微信小程序应设置侵权投诉机制，处理用户间的权益纠纷。」**
> 3.13：须向用户披露「投诉渠道」。

这不是"最好有"，是**审核时会看的**。而且 CreatorBox 的业务性质（解析他人平台内容）本身就是侵权投诉的高风险区 —— **没有投诉机制，等于把最大的下架触发点留在盲区**。

### 1.1 与之配套的强制约束（官方数据）

| 约束 | 数据 | 后果 |
|---|---|---|
| 投诉处理时效 | **收到投诉 10 日内联系用户，30 日内办结** | 超时进小程序审核红线 |
| 交易投诉核心时效 | **48 小时**（核实→和解→平台介入→凭证→申诉） | 超时触发平台处罚 |
| 投诉渠道披露 | 3.13 要求明示投诉渠道 | 未披露违反 3.13 |
| 客服能力 | 微信强制每个小程序有联系渠道，右上角「…」→「反馈与投诉」 | 该入口的反馈**运营方都能看到** |

> ⚠️ 注意「反馈与投诉」是微信强制注入的全局入口。**即便你不在小程序里做客服按钮，用户投诉也会进来。** 所以后台必须有工单承接能力，不能靠"等微信通知我再看"。

### 1.2 侵权投诉的官方流程（后台要能承接）

```
权利人提交投诉（书面通知书 + 权属证明 + 侵权证明）
    → 平台转交开发者
    → 开发者举证 / 主动联系权利人
    → 平台介入判定
```
必要动作：
- **联系方式留存**（1.1 要求提供可联络的链接或邮箱）→ 后台需要能对外展示的客服邮箱/链接
- **投诉工单化**（10 日 / 30 日时效倒计时）
- **处理日志留存**（谁在什么时候处理的、怎么处理的）
- **主动下架能力**（被投诉素材一键封禁，避免继续传播放大责任）

## 2. 后端要做的 5 个模块

| # | 模块 | 优先级 | 为什么 |
|---|---|---|---|
| 1 | **合规中心** | 🔴 **P0** | 3.10 硬要求 + 侵权风险最高的业务，必须有 |
| 2 | **平台健康度** | 🔴 **P0** | 解析成功率跌破阈值 = 平台改版预警，这是 CreatorBox 的生命线 |
| 3 | **广告运营** | 🟡 P1 | eCPM 看板、频次调优、收益核算 |
| 4 | **用户与权益** | 🟡 P1 | 会员、限次、封禁、退款、注销 |
| 5 | **内容安全** | 🟢 P2 | 若接入 UGC 审核则升为 P0 |

### 2.1 合规中心（P0，不可省）

```
投诉工单
├── 来源：微信「反馈与投诉」/ 站内举报 / 邮箱
├── 类型：侵权（版权）/ 隐私 / 内容违规 / 功能故障 / 退款
├── 时效：10 日联系、30 日办结 → 自动倒计时 + 超时预警
├── 处理：联系用户 / 举证材料上传 / 素材下架 / 拒绝并说明
└── 留痕：全部操作写审计日志（不可删除）
```
**配套的免责设计**（减少纠纷而不是只处理纠纷）：
- 结果页 12px 灰字免责
- 用户协议写明「需确保拥有合法使用权」
- 投诉页内置「我确认已获作者授权」勾选

### 2.2 平台健康度（P0，最被低估的一块）

**这是 CreatorBox 特有的、别的项目没有的模块。** 因为解析服务依赖平台接口，平台改版随时发生。

```
解析监控
├── 各平台成功率（抖音/快手/小红书/B站/微博 独立统计）
├── 三级通道命中率（Feed 接口 → slidesinfo → 移动端 SSR）
├── 失败样本归档（可复现 → 适配时直接用）
└── 🔔 告警：成功率 < 阈值 立即推送
```
**没有这个，平台改版 = 用户流失几天你才知道。** 有了这个，当天就能收到告警并降级。

> 建议阈值：单平台成功率跌破 70% 告警；跌破 40% 自动降级到"仅支持已验证平台"并在端上提示。

### 2.3 广告运营（P1）

- 激励视频 eCPM 实测（对照行业 50–120 元区间）
- 广告位曝光量、填充率、点击率
- **频次调优**：激励视频的展示频次直接影响留存，需 A/B 对照
- 收益日报（微信流量主后台是 T+1 结算，运营侧要看趋势）

### 2.4 用户与权益（P1）

- 会员状态、限次配额（激励视频兑换的免费次数）
- 封禁（违规用户 / 恶意刷量）
- 退款与订单
- **账号注销**（3.4.1 要求：用户注销后须相应删除数据）

### 2.5 内容安全（P2，视情况升 P0）

⚠️ **判断标准**：如果小程序只是"解析链接 + 展示结果"，属于纯工具（可豁免接入）；**但如果允许用户上传图片/视频到素材库，就构成 UGC，必须接入审核**。

- 微信官方 `msgSecCheck` / `imgSecCheck` / `mediaCheckAsync`（最低合规）
- 腾讯云 IMS（进阶，6 维度 + AI 生成识别 + 自定义策略，100 QPS，工具类规模年费 0–2000 元）
- ⚠️ 视频必须用**异步接口 + 回调**，不能同步处理后先发布
- 审核接口**只能服务端调用**，前端直调会泄露密钥
- 必须有**兜底策略**：接口超时默认拦截，不可异常放行

## 3. 技术选型

| 层 | 选择 | 说明 |
|---|---|---|
| 框架 | **Vue3 + Vite + TypeScript**（Admin 侧） | 与 GEO Optimizer 保持一致，组件可复用 |
| 后端 | **FastAPI + PostgreSQL + Redis** | 完全沿用现有栈，运维熟悉 |
| 部署 | 宝塔 + Nginx，与 API 同机 | 2C2G 够用（视频精修另需 GPU 机） |
| 认证 | JWT + RBAC（3 角色：超管/运营/客服） | 早期 1 人可不分角色，但表结构要留 |

**关键：一期做单租户，但表结构预留。**

```sql
-- 所有业务表预留
tenant_id  UUID DEFAULT 'default' NOT NULL
```
将来要分租户，加 `WHERE tenant_id = ?` 即可，不用重构。

## 4. 排期与工作量

| 阶段 | 周期 | 内容 |
|---|---|---|
| **B1 后台骨架** | 与 M1 小程序并行 | 表结构 + RBAC + 合规中心（工单 + 时效倒计时 + 审计日志） |
| **B2 监控看板** | M1 期间 | 平台健康度 + 告警推送 |
| **B3 广告与用户** | M2 期间 | eCPM 看板、限次、会员、注销 |
| **B4 内容安全** | 视是否 UGC | 审核队列 + 人工复核 |

> **后台不能拖到 M2 之后。** 因为合规中心是 3.10 硬要求 —— 提审时没有就会被驳回。**必须与 M1 小程序同步开发。**

## 5. 与 GEO Optimizer 的关系

| | CreatorBox 后台 | GEO Optimizer 后台 |
|---|---|---|
| 租户 | 单租户 | 多租户（目标 10000 用户） |
| 核心 | 合规中心 + 平台健康度 | 报告广场 + 代理分销 + 白标 |
| 计费 | 无（广告变现） | ¥0 / ¥299 / ¥999 订阅 |

**可复用**：Vue3 Admin 框架、RBAC 基础组件、FastAPI 后端骨架、Nginx/宝塔运维经验。
**不可复用**：业务模块全部不同，**不要强行合并成同一个代码库** —— 生命周期、迭代节奏、合规风险都不一样，绑一起会互相拖累。

---

## 6. 一句话总结

> **后台要做，但做「自用运营后台」，不做「SaaS 多租户」。**
> 其中 **合规中心是微信 3.10 的硬性审核项，必须与小程序同步开发，不能拖**；
> **平台健康度**是 CreatorBox 独有的生命线模块（平台改版预警）。
> 表结构预留 `tenant_id`，将来需要时零成本拆分。

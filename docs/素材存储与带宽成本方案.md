# 素材存储方案（带宽成本控制）

> 版本 v1.0 ｜ 2026-10-04
> 决策：**不存我们的服务器**，仅在"保存到相册"时临时中转，用完即删

---

## 0. 直接回答

**都不选。视频和图片都不长期存我们的服务器。**

分两种情况：

| 场景 | 流量走法 | 我们的成本 |
|---|---|---|
| **在线预览** | 平台 CDN → 用户设备，**我们只返回一个地址** | **¥0** |
| **保存到相册** | 平台 CDN → **我们临时中转** → 用户设备 → **立即删除** | 一次 CDN 流量 |

**关键认知：我们的服务器只是一个"地址翻译器"，不是"素材仓库"。**

| 方案 | 月流量 | 月成本 | 评价 |
|---|---|---|---|
| **A 不存，只透传** | 0 | **¥0** | ✅ 最优 |
| B 存服务器中转（CDN） | 4.3 TB | **¥923** | 可接受（视频场景） |
| C 存对象存储做素材库 | 4.3 TB + 存储费 | **¥923 + ¥430** | ❌ 双份花钱 |

### 🔴 图集是成本炸弹

| 场景 | 月流量 | 月成本 |
|---|---|---|
| 视频（2 次/月） | 4.3 TB | **¥923** |
| **图集（2 次/月 × 9 张）** | **39.5 TB** | **¥8306** 🔴 |

**图集成本是视频的 9 倍。** 这直接决定了图集的配额策略（见 §4）。

## 2. 为什么"必须中转"只是权宜之计

### 微信小程序的硬约束

| 资源类型 | 白名单要求 |
|---|---|
| **图片** `<image>` | **必须**在 `downloadFile` 合法域名 |
| **视频** `<video>` | 走业务域名，**限制宽松** |

⚠️ **平台的 CDN 域名（`v*.douyincdn.com` 等）不可控** —— 子域名众多且会变，无法全部加入白名单。

### 由此产生的两个选项

| 选项 | 说明 |
|---|---|
| **B1 中转（推荐起步）** | 我们的域名加入白名单，中转时 Nginx `sendfile on` |
| B2 让用户手动复制 | 体验太差，❌ |

> 💡 **中转是"流量换体验"的必要妥协**，不是技术选择。**但它只在用户点"保存"时才发生**，预览时不中转。

## 3. 具体的存储策略

### 3.1 存储分层

| 数据类型 | 存哪 | 保留多久 | 说明 |
|---|---|---|---|
| **解析结果元数据** | ✅ PostgreSQL | 永久（可配） | aweme_id、标题、作者、封面地址 |
| **解析结果缓存** | ✅ Redis | **10 分钟** | 同一视频重复解析不打平台 |
| **视频/图片文件** | ❌ **不存** | — | 只透传地址 |
| **中转临时文件** | ⚠️ 本地磁盘 | **5 分钟自动删** | 仅保存动作产生 |
| **免费用户历史记录** | ✅ PostgreSQL | **7 天** | 只存元数据不存文件 |
| **会员历史记录** | ✅ PostgreSQL | **永久** | 同上 |

### 3.2 中转实现

```python
# 保存到相册的中转接口
@router.get("/proxy/{token}")
async def proxy_media(token: str, request: Request):
    """
    1. 从 Redis 取真实地址（token 是我们生成的短期凭证）
    2. Nginx sendfile 直接透传，不落盘
    3. 返回视频流
    """
    info = await redis.get(f"proxy:{token}")
    if not info:
        raise HTTPException(404, "链接已过期")

    # 关键：用 X-Accel-Redirect 让 Nginx 内部重定向
    # 不经过 Python 进程，不占内存
    return RedirectResponse(url=info["url"], status_code=302)
```

**Nginx 配置（关键优化）：**

```nginx
location /proxy/ {
    internal;                          # 外部无法直接访问
    proxy_pass $upstream_cdn;
    proxy_set_header Host $upstream_host;
    proxy_buffering off;               # 不缓冲，直接流式返回
    proxy_set_header Range $http_range; # ⭐ 视频拖动进度条必需
    expires 5m;                        # CDN 侧 5 分钟缓存
    add_header Cache-Control "private, no-store";
}
```

⚠️ **两个必须注意的点：**
1. **`proxy_buffering off`** —— 开启缓冲会把整个文件读进内存，25MB 文件会占满带宽
2. **`Range` 头必须透传** —— 微信的 `video` 组件依赖 HTTP Range 做进度条拖动

## 4. 图集的成本控制（关键）

⚠️ **图集是带宽重灾区，成本是视频的 9 倍。必须严格限次。**

| 规则 | 免费 | 会员 |
|---|---|---|
| 图集解析次数 | 每日 3 次 | 不限 |
| **图集下载次数** | **每月 2 次** | 不限 |
| **免费返回张数** | **仅前 3 张预览** | 全部 |
| 提示 | "开通会员查看全部 N 张" | — |

**「免费只给 3 张预览」是很好的转化钩子：**
- 用户看到一半被打断，付费意愿明显上升
- 我们的带宽成本可控（3 张而非 9 张，成本降 67%）
- 且不显得抠 —— 因为已经给了 3 张

## 5. 免费额度设计（结合存储成本）

| 项 | 免费 | 会员 | 成本影响 |
|---|---|---|---|
| **解析** | **不限次** | 不限 | ¥0（只是 HTTP 请求） |
| **视频保存** | 每日 2 次 | 不限 | 每日 2×25MB×3000 = 1.5GB/天 |
| **图集保存** | **每月 2 次** | 不限 | 每月 2×9×25MB×3000 = 1.35TB/月 |
| **批量下载** | 每日 1 条 | 不限 | ⚠️ 批量会放大 N 倍成本 |

⚠️ **批量下载必须算成本**：一次导入 20 条 = 500MB。所以：
- 免费：批量每日 1 条（且单条也算配额）
- 会员：批量不限，但要走**队列限速**（防止单用户刷爆带宽）

## 6. 3000 日活的月度成本预估

| 项 | 流量 | 成本 |
|---|---|---|
| 视频保存（免费 每日2次 + 会员约6% 不限） | ~5 TB | **¥1,050** |
| 图集保存（免费 每月2次 + 会员不限） | ~40 TB ⚠️ | **¥8,400** |
| 素材库存储（元数据为主） | — | ¥20 |
| **合计** | **45 TB** | **¥9,470** |

### 🔴 这个数字超出广告收入

3000 日活的广告收入约 **¥5,400/月**（激励视频 2 次/天 × eCPM 60 × 50% 分成）。

**如果图集全量放开，成本 ¥9,470 > 收入 ¥5,400 → 亏损。**

### ✅ 解决方案（三选一或组合）

| 方案 | 效果 |
|---|---|
| **① 图集严格限次（每月 2 次）+ 会员不限** | 会员比例低时成本可控 |
| **② 图集做成付费功能**（单独点数包） | 不占会员权益，单独收费 |
| **③ 图集只返预览图，下载走"集成分享"** | 成本降 90% |

**我的建议：① + ②。** 图集对小红书用户是刚需，直接砍掉会流失用户；但**不该无限送**。

## 7. 隐私优势（顺带的卖点）

**我们不存素材 = 我们的服务器上没有用户的内容。**

这条在合规上极有价值：
- 素材版权归属原作者，我们只是"跳转"
- 用户不需要担心"素材被平台留存"
- 一旦被投诉，我们**没有内容可被下架**（只有元数据记录）

⚠️ 但**元数据也要设保留期**（免费 7 天），避免长期留存标题/作者信息。

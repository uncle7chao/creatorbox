## 0. 项目本质（先对齐认知）

**一句话**：CreatorBox 是「素材不留在别人服务器里」的**素材采集 + 净化工具**。

- **用户来干什么**：贴个抖音链接 → 拿到素材 → 去水印/去字幕
- **我们凭什么存在**：端侧完成 80% 的像素处理，**素材不出设备**
- **我们靠什么赚钱**：流量激励视频（主）+ 9.9 元订阅（辅）

**不做什么**（同样重要）：
- ❌ 不做「资源溯源型去水印」（即用正则提取 URL 里的 vid 参数拼地址）—— 那是审核最敏感的雷区，随时失效
- ❌ 不做 SaaS 多租户 —— 无企业客户
- ❌ 不自研签名逆向 —— X-Bogus 已死、a_bogus 每周迭代
- ❌ 不宣称能"去除 AI 水印" —— 只能做"检测与举证"

## 4. 🔴 M0 可行性验证（2 周，最关键）

**这是 Gate。不是走流程，是三个"是/否"问题，任意一个为否就要改设计。**

### V1 · 分享 Intent 是否成立？ ⭐ 最高优先级

**问题**：抖音/小红书/快手的分享面板，是否真的走系统 `ACTION_SEND`？

**为什么致命**：这是小程序采集的主链路。抖音有大量自定义 scheme（`snssdk1128://aweme/detail/{id}`）和自研分享 SDK，**可能走私有通道而不是系统分享面板**。若不成立，整条主链路要重新设计。

**做法**：
1. 写一个最小 Android Demo，只注册 `ACTION_SEND` 接收器
2. `onNewIntent` 里把 Intent 的 action / type / data / extras **全部打印**
3. 真机逐个平台：抖音 → 分享 → 微信 → 选中 Demo
4. 对比三个平台的 Intent 内容差异

**安卓必踩的坑**：
- `intent-filter` **必须与 `ACTION_MAIN` 分成两个**，否则系统只按 MAIN 匹配、分享被静默忽略
- Android 12+ 必须显式 `android:exported="true"`

**降级方案（若失败）**：监听剪贴板 + 引导用户手动粘贴，走解析服务。**这条路 100% 可用**，只是体验差一截。

**iOS 同步验证**：Share Extension + `NSItemProvider.loadItem(forTypeIdentifier: UTType.url.identifier)` + App Group 传数据。

---

### V2 · MI-GAN 许可证 + 端侧可行性

**两个问题，一个都不许跳。**

**问题 A（商务）**：MI-GAN 的许可证是什么？
- Timeline Studio 标 MIT，但那只覆盖它自身代码，**未标注模型许可**
- 需找到 MI-GAN 原始仓库/权重页，确认授权条款
- **拿不到明确书面授权 → 改用 LaMa（Apache-2.0）**

**问题 B（技术）**：TFLite/CoreML 转换后在真机上跑得动吗？
1. 下载 MI-GAN 权重，转换 TFLite（FP16）
2. 验证能否加载（有无被禁算子）
3. Android 真机测速（GPU delegate + NNAPI）
4. iOS 真机测速（CoreML + ANE）
5. **实测 512×512 耗时是否 <150ms**

**备用方案**：LaMa INT8 44MB，已有 Qualcomm AI Hub 官方实测背书（S23 Ultra NPU 87ms）。

---

### V3 · 小程序审核尺度实测

**做法**：做一个**功能完整但内容极简**的测试版小程序提审。
- 类目选「工具 → 效率」
- 文案只用「视频解析」「素材获取」，**完全不出现"去水印"**
- 结果页带 12px 免责灰字 + 用户协议

**要观察的**：驳回理由是什么？是类目问题、文案问题、还是功能问题？

**为什么必须做**：去水印类小程序是下架重灾区。**与其开发完 3 个月被驳回，不如花 3 天探明尺度。**

## 5. M1 小程序 MVP（3–4 周）

### 5.1 功能清单

| 模块 | 功能 | 优先级 |
|---|---|---|
| **采集** | 分享接收 + 剪贴板监听 + 手动粘贴（三通道） | P0 |
| **解析** | 抖音 / 快手 / 小红书 / B站 / 微博，五平台 | P0 |
| **素材库** | 列表 / 预览 / 保存到相册 / 配额显示 | P0 |
| **广告** | 激励视频（3 个触发点）+ 插屏 + Banner | P0 |
| **会员** | 9.9 订阅 + 权益展示 + 配额扣减 | P0 |
| **合规** | 免责页 + 协议 + 举报入口 + 投诉渠道 | P0 |
| **后台** | 合规中心 + 平台健康度 | P0 |

### 5.2 关键设计点

**解析三级降级链**（借鉴 ucmao/media-parser）：
```
一级：抖音移动端 Feed 接口 (api5-normal-c-hl.amemv.com/aweme/v1/feed/)
      → 免 Cookie 免签名，403 率 0%，约 200ms
二级：iesdouyin.com/web/api/v2/aweme/slidesinfo/ 公开接口
三级：iesdouyin.com/share/video/{id} 移动端 UA 抓 SSR _ROUTER_DATA
失败：终端状态短路熔断（私密/已删除链接 2 秒内返回，不无谓重试）
```

**代码来源**（均为 MIT，可商用）：
- `parse-video-py` → 解析器抽象 + FastAPI 骨架 + 接口契约
- `ucmao/media-parser` → 小红书双 UA 回退 + 短路熔断

**必须做的两个成本控制**：
- 解析默认返 **720p** 而非原分辨率
- 在线预览走 **`<video>` 组件指向平台 CDN**（域名校验比图片宽松，零流量成本）

**必须做的合规动作**：
- 类目「工具 → 效率」
- 文案避开「去水印 / 破解」
- 结果页 12px 灰字免责
- 协议首次强制弹窗（可滚动 + 二次确认）
- 服务器中转（因 saveVideoToPhotosAlbum 需 downloadFile 白名单），Nginx `sendfile on`

### 5.3 排期拆分

| 周 | 任务 |
|---|---|
| W1 | 后端骨架 + 数据库表结构（预留 tenant_id）+ 解析服务（抖音+快手） |
| W2 | 解析服务（小红书+B站+微博）+ 三级降级 + 健康度埋点 |
| W3 | 小程序前端（采集/素材库/合规页）+ 广告接入 + 会员 |
| W4 | 管理后台骨架（合规中心 + 健康度看板）+ 联调 + 提审 |

## 6. M2 App 图片去水印（3–4 周）

| 周 | 任务 |
|---|---|
| W1 | Flutter 工程 + Platform Channel 打通 + 相机/相册选图 |
| W2 | L1 框选 UI（手势放大/精调）+ **L2 调和扩散算法移植**（Kotlin 原生） |
| W3 | L3 MI-GAN 推理接入（LiteRT + CoreML）+ 模型分发（首次下载后本地缓存） |
| W4 | 元数据净化（C2PA/EXIF/零宽字符）+ 分享保存 + 真机测试 |

**技术要点**：
- L2 调和扩散：纯像素运算，Kotlin/Swift 直接实现，**无模型无依赖**（移植 pamelaaaaa1218 的算法思路，不复制代码）
- L3 模型**首次使用时下载**并缓存，不要塞进安装包（否则安装包 +16MB 转化率会掉）
- 集成进相册/分享面板：**「分享到 CreatorBox」入口**

## 7. M3 App 视频去水印（4–5 周）

| 周 | 任务 |
|---|---|
| W1 | 视频解码 → 帧序列 → ROI 裁剪 → 编码回写（性能验证） |
| W2 | 跨帧稳定性检测（过滤移动的水印）+ ROI 跟踪 |
| W3 | **时序一致性**：光流对齐 + 时序混合 + 边缘 blend（抄 remove-ai-watermarks 思路） |
| W4 | 分级导出（免费快速版 / 订阅高清版）+ 云端精修接入 |
| W5 | 30fps 1080p 性能优化 + 长时间处理稳定性 |

**技术要点**：
- **ROI 裁剪是可行性关键**：水印框通常占画面 10–20%，裁到（如 1080×200）后 MI-GAN 在 512×512 上推理 —— 恰好落在移动端实测甜点区
- **逐帧闪烁的解法不是换模型，是时序复用**（纯几何运算，端侧 CPU 可完成）
- 云端用 E2FGVI（MIT），**不引入 ProPainter**

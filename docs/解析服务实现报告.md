## 3. 关键设计

### 3.1 缓存 key 用短链，不用原文

⚠️ **踩过的坑**：最初用原始文本做 key，导致「带分享文案」和「纯链接」命中两份缓存。修复后：

```
第1次（带文案）  3.82s  cached: False
第2次（纯链接）  0.004s cached: True   ← 正确命中
```

### 3.2 平台改版预警

`/api/health` 自动计算失败率，超 40% 返回 `degraded: true` + `alert`。这是纯解析路线唯一的生命线。

### 3.3 签名平台隔离

小红书/快手实测受阻（见 §5），用 `CB_ENABLE_SIGNED=0` 默认关闭，避免影响抖音主链路。

## 5. 小红书 / 快手：实测受阻

### 5.1 小红书

| 尝试 | 结果 |
|---|---|
| 访问 `/explore` | ❌ 重定向到登录页 |
| `__INITIAL_STATE__` | ✅ 存在但**无 note 数据**（游客态） |
| `/api/sns/web/v1/homefeed` | ❌ HTTP 500 `create invoker failed, service: jarvis-gateway-default` |

**原因**：需要 `x-s` / `x-t` 请求签名。

### 5.2 快手

| 尝试 | 结果 |
|---|---|
| 访问首页 | ✅ **无登录墙**，9 个 cookie（含 `did`） |
| `/rest/v/feed/hot` | ❌ `{"result":11,"error_msg":"请检查下网络连接是否正常"}` |

**原因**：需要 `__clientid` / GraphQL 签名。

### 5.3 已写入的骨架

`parsers/signed_platforms.py` 包含：
- `XhsParser` / `KuaishouParser`（B 方案：页面内提取，不需逆向签名）
- 域名匹配（已测试 5 项全对）
- 已知字段名：快手 `srcNoWatermark`、小红书 `urlDefault`/`originVideoKey`

**开箱方式**：设 `CB_ENABLE_SIGNED=1` 启用（需先补上签名逻辑）。

## 6. 部署要点

```bash
# 环境
pip install -r requirements.txt
# ⚠️ 不需要 playwright install（用 channel="chrome" 复用本机 Chrome）
#   服务器上需安装 Google Chrome

# 启动
CB_INSTANCES=2 uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `CB_INSTANCES` | 1 | 浏览器实例数（每实例内存 500MB-1GB） |
| `CB_HEADLESS` | 1 | 无头模式 |
| `CB_REDIS_URL` | 空 | Redis 连接串（不设用内存缓存） |
| `CB_CACHE_TTL` | 600 | 缓存秒数 |
| `CB_RATE_LIMIT` | 30 | 每分钟请求上限 |
| `CB_API_KEY` | 空 | API 鉴权（不设则不鉴权） |
| `CB_ENABLE_SIGNED` | 0 | 是否启用小红书/快手 |

### 资源需求

| 规模 | 配置 | 月成本 |
|---|---|---|
| 验证期 | 2C4G × 1 实例 | ¥100–200 |
| 1000 DAU | 4C8G × 2 实例 | ¥400–600 |
| 3000 DAU | 8C16G × 4 实例 | ¥1200–2000 |

⚠️ **浏览器实例固定成本是主要支出**，高于带宽成本。

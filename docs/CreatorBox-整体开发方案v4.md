# CreatorBox 整体开发方案 v4（2026-10-11）

> 取代 v3（2026-10-05）。v3 期的「解析纯 HTTP 化 + 多平台接入」已完成收官，
> v4 的主命题：**把产品从「单一解析工具」推进为「创作者工具矩阵 + 三端布局」**，
> 同时不偏离上架主线。

---

## 一、架构总纲：按「成本承担者」分层

所有功能先回答一个问题：**跑的时候谁出资源？**

| 层 | 成本承担者 | 特征 | 承载端 |
|---|---|---|---|
| **基础层** | 我们的服务器（近零边际成本：302 直链/纯计算/静态词库） | 秒级、无落盘 | 小程序（主力）+ 全端共享 |
| **扩展层** | 用户设备（宽带/磁盘/挂机时间） | 持续占用、大文件 | PC 端 + App 端专属 |
| **受限层** | 需要资质（企业主体/算法备案/支付商户号） | AI 生成、虚拟支付 | 资质到位前不开发 C 端入口 |

判断口诀：**服务器要「陪着」的功能不做进小程序；小程序只做「点一下就完」的功能。**

## 二、三端规划

### 2.1 端的分工

| 端 | 定位 | 技术线 | 状态 |
|---|---|---|---|
| 小程序 | 基础功能 + 获客主战场（微信生态裂变） | 原生 | ✅ 功能面完成，等上架 |
| App | 扩展功能（直播录制/无上限批量/4K） | **Flutter（Android 先行）** | **P1 骨架已建（10-11）** |
| PC | 扩展功能全量 + 官网直发免商店审核 | **Flutter Desktop（与 App 同码线）** | **P1 骨架已建（10-11）** |

> ⚠️ 三端 ≠ 三套代码：小程序保持原生，App+PC 共用 Flutter 一条代码线。
> 绝不允许出现三套独立技术栈。

### 2.2 扩展功能清单（Flutter 端专属，全部用户设备出资源）

1. 直播录制（ffmpeg `-c copy` 拉流转存，零 CPU；对口平台：B站/抖音/快手/虎牙）
2. 直播回放下载（回放是 VOD，直接复用服务端解析）
3. 无上限批量下载（本地下载管理器语义：队列/断点/历史/重命名）
4. 4K/原画档位（大文件走用户带宽）
5. 音频/字幕/封面分轨下载
6. 桌面级体验：完成提示音、自动更新、开机自启

### 2.3 国际平台的功能分层（2026-10-11 用户拍板）

> 原理：解析软件运行在哪个环境，那个环境的网络就决定连通性。
> 小程序端受微信沙箱锁死（域名白名单 + 无自由网络栈 + 大陆用户物理不通），
> **依赖用户环境网络的能力全部归 App/PC 端**。

| 能力 | 小程序 | App/PC | 说明 |
|---|---|---|---|
| TikTok/X 解析（服务端已通） | ✅ 保留 | ✅ 保留 | HK 服务器代解析，不受用户环境影响——这是小程序端的差异化卖点，不砍 |
| YouTube 下载 | ❌（IP 锁死路） | ✅ **本机引擎** | App 端嵌 `youtubedl-android`、PC 端嵌 `yt-dlp`：解析跑在用户设备，googlevideo IP 锁天然消解 |
| 直播录制 | ❌ | ✅ | 用户设备挂机拉流（v4 既有决策） |
| 4K/原画 + 无上限批量 | ❌ | ✅ | 大文件走用户带宽 |
| **本机解析引擎（新增）** | ❌ | ✅ | App/PC 本地跑解析，**用户环境决定连通性**：能上外网的用户直连零服务器成本；失败自动回退服务端 API（HK） |

**App/PC 国际功能实现路线**：

- **PC 端**：内嵌 `yt-dlp`（Unlicense）+ 本地下载管理器（队列/断点/历史——Yeguo-IDM 与 m3u8-dl 的成熟模式已拆解入库）
- **App 端**：`youtubedl-android 0.18.1`（生态验证的 Seal/KDownloader 模式）；iOS 端 App Store 审核对下载类高危，PC 网页直发兜底
- **回退链**：本机引擎失败 → 服务端 API（HK 出口）→ 两层都失败才报错；国际组收敛开关同样适用于 Flutter 端

### 2.4 账号中台（✅ 数据层+API 已落地，2026-10-11）

- ~~现状：用户表以微信 `openid` 为主键 → 跨端即碎~~ → **已解决**：`users.user_id` 跨端主键 + `identities` 绑定表（存量 8 用户已自动回填+播种 wechat_mini 身份），openid 全链路零改动
- 桥接绑定闭环已上线：`bridge/create`（App/PC 换一次性 6 位码）→ `bridge/confirm`（小程序输码确认）→ `bridge/poll`（签发 90 天 token）→ `/api/auth/me`（token 换账号全貌）
- 安全：码 5 分钟 TTL + 一次性 + 5 次防爆破锁定 + 身份冲突预检；token 90 天滚动
- 专项测试 31 断言全绿（含旧库迁移模拟）+ 真实服务 e2e 通过
- 待办：Flutter 端接入时补「小程序输码确认」UI（会员页入口）
- 会员权益升级为「全端权益」：小程序会员在 PC/App 解锁扩展功能 → **反哺小程序会员转化**

### 2.5 三端联动漏斗

```
PC 端免费工具（拉新，无审核摩擦）
   ↓ 扫码登录同账号
小程序（高频使用 + 会员转化）
   ↓ 会员=全端权益
App/PC 扩展功能（深度留存）
```

### 字幕独立获取 · spike 结论（2026-10-11）

实测三个主力平台的 `/api/parse` 响应：

| 平台 | subtitle_text | 响应里的字幕相关字段 |
|---|---|---|
| 抖音 | 0 字 | 无（空列表）|
| B站 | 0 字 | 无 |
| 快手 | 0 字 | 无 |

**结论：这不是「接口没接」，而是数据源层面就没有**。现有实现只有 YouTube
（`intl/ytdlp_engine.py` 的 `attach_subtitle`）能从 ytdlp 拿字幕。

要往下做需要：
- **B站**：先攻克 wbi 签名门槛（与「多档解析」是同一个卡点，见下条），再调
  `/x/player/v2` 拿 subtitle 列表 → 下载 vtt 并转纯文本
- **抖音**：需逆向确认是否有公开字幕接口（video 没有独立字幕文件，
  字幕可能只嵌在视频流或评论区，需抓包验证）
- **小红书**：图集视频的字幕同理待确认

⚠️ 建议：这两项与「B站 wbi 签名」是**同一个前置卡点**，建议合并成一个专项
（wbi 打通后，B站多档 + 字幕一起解决），而不是分别投入。

**探针样本池剩余工作**：目前仅 kuaishou 有备选样本，其余 8 个平台仍是单样本。
补样本的规矩（务必遵守）：
1. 新样本必须**实测 `/api/parse` 成功**才能入池 —— 填未验证样本 = 探针变噪音源
2. **不要从测试代码里抄链接**（大量是 `v.douyin.com/abc` 这类伪造占位符）
3. 已实测**不可用**（勿再塞回）：`v.douyin.com/hZMkNvXLtLc`（0 档）、
   小红书无 `xsec_token` 的裸链（0 档）
4. 加进 cfg 的 `urls` 列表即可，**不必重复列 `url` 本身**（`_sample_urls` 会自动置首）

### 3.3 上架主线（不变，最高优先级）

1. 正式注册小程序账号（个人主体，免费）
2. 域名 ICP 备案确认（iyama.cn 备案状态核查；香港服务器不能备案）
3. 服务部署大陆服务器 + HTTPS + 小程序后台合法域名
   ⭐ **2026-10-11 用户拍板：生产主部署 = 大陆服务器**（流量主/广告变现要求备案域名，
   HK 不能备案）。国际平台在服务端默认关闭（CB_INTL_ENABLED=0），
   由 App/PC 本机引擎承载（§2.3）；HK 内部转发为灰色可选项，默认不做。
   部署套件见 deploy/（pack.ps1 / install.sh / verify-cn.sh / service 模板）
4. 用户隐私保护指引 + 类目（工具）
5. 提审版收敛开关：服务端下发各平台解析入口可见性（半天工作量，待做）

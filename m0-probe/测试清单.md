# M0-V1 分享 Intent 验证 · 测试清单

> 这是整个项目最关键的一个验证。**任意一个平台走通，M1 的采集主链路就成立。**

---

## 为什么要做这个验证

小程序采集素材的**主链路**是：用户在抖音点「分享」→「微信」→「CreatorBox」，我们直接拿到链接。

**风险点**：抖音/小红书/快手都有自研分享 SDK 和大量自定义 scheme（如 `snssdk1128://aweme/detail/{id}`），**可能走私有通道而不触发系统 `ACTION_SEND`**。那样的话，用户在分享面板里根本看不到我们，整个主链路要重新设计。

**降级方案**（100% 可用，只是体验差一截）：监听剪贴板 + 引导用户手动粘贴。**所以最坏情况不是做不了，是要多做一个粘贴页。**

## 二、测试步骤（四个平台逐个测）

### 每个平台都做这三步

| 步骤 | 操作 | 记录什么 |
|---|---|---|
| ① | 打开目标 App，找到一个视频，点**分享** | 分享面板里**能不能看到「CB探针」** |
| ② | 选它，看能否拉到数据 | 抓到的 `EXTRA_TEXT` 内容是什么 |
| ③ | 打开 CB探针，点「2. 读剪贴板」 | 剪贴板里有没有链接 |

### 平台清单

- [ ] **抖音** —— 分享面板出现 CB探针了吗？抓到什么？
- [ ] **小红书** —— 分享面板出现 CB探针了吗？抓到什么？
- [ ] **快手** —— 分享面板出现 CB探针了吗？抓到什么？
- [ ] **视频号**（可选）
- [ ] **B站**（可选）

### 另外测一下图文作品

抖音和小红书的**图文（图片轮播）**分享走的是 `image/*` 或 `text/plain`，和视频不一样，建议单独测一次：

- [ ] 抖音图文分享 → 能否拉到什么？
- [ ] 小红书图文分享 → 能否拉到什么？

## 三、结果判定

### ✅ 走通（主链路成立）

- 分享面板**能看到** CB探针
- 抓到的 `EXTRA_TEXT` 里**能提取到 `https://` 链接**
- 链接短链 302 后**能提取到视频 ID**

→ **M1 采集主链路成立**，按原计划开发。

### ⚠️ 部分走通

- 能收到 Intent，但**提不出链接**（比如只有一段分享口令文本）
  → 需要写口令提取正则，**可修复**
- 视频能走通，**图文走不通**
  → 采集只做视频，图文用剪贴板兜底

### ⛔ 完全走不通

- 分享面板**根本看不到** CB探针
  → 主链路不成立，**必须切到剪贴板方案**
  → 但这也是好消息：早发现比开发完 3 个月被推翻好
  → 此时小程序改为「粘贴链接」为主入口，App 端用 Share Intent + 手动粘贴双通道

## 四、抓到的数据怎么看

日志里这几行最关键：

```
=== ON_NEW_INTENT ===
  action   : android.intent.action.SEND        ← 是 SEND 就对了
  type     : text/plain
  EXTRA_TEXT : 7.68 复制打开抖音，看看【xxx】https://v.douyin.com/xxxxx/
  --- 文本分析 ---
    ✅ 提取到 1 个链接:
      [0] https://v.douyin.com/xxxxx/
      → HTTP 302
      → 视频ID: 7123456789012345678 ✅
      → 域名: www.douyin.com
```

| 看什么 | 说明 |
|---|---|
| `action` | 是 `ACTION_SEND` 就说明系统通道正常 |
| `EXTRA_TEXT` | 抖音通常给一段带口令的文本，链接藏在里面 |
| 提取到链接数 | 0 = 拿不到，需要想别的办法 |
| HTTP 状态 | 302 说明短链跳转正常 |
| 视频ID | 提取到 = 解析链路完全打通 ✅ |
| 域名 | 确认跳到哪个平台 |
